# VDE 1.3.0 Hardening Design: The Sovereign Evolution

## Objective
Deepen the integration between the technological pillars and the Mandalorian mandates of the Forge by implementing automated gatekeepers, dynamic resource management, and enhanced observability.

## 1. THE PRE-STRIKE SENTINEL (Automated Pre-Commit Guard)
**Architecture**: A ZSH-native git hook installed via `bin/install-githooks`.
**Components**:
- **Impurity Scanner**: Scans staged `.zsh` and `.sh` files for `#!/bin/bash` or `#!/bin/sh` shebangs.
- **Secret Sentinel**: Regex-based search for hardcoded credentials (API keys, passwords) in staged code.
- **Silent Spine Check**: Runs `bin/vde-spine-check.zsh` to ensure the Tetrad is active before any commit.
**Outcome**: Impure or broken commits are "incinerated" (blocked).

## 2. RESOURCE-AWARE IGNITION (Dynamic Scaling)
**Architecture**: Update `bin/vde start` to query system resources.
**Logic**:
- Replace the static 3-VM limit with a "System Breath" check.
- Query `docker info` and `sysctl` (or `/proc/meminfo`) to assess CPU/Memory ore.
- Calculate capacity: `max_vms = min(3, system_capacity_based_on_load)`. Allows scaling up on powerful machines and throttling on constrained ones.

## 3. IDENTITY PULSE (Active Bridge Monitoring)
**Architecture**: A health-check mechanism within the `vde` orchestrator.
**Logic**:
- Before any `vde enter` or `vde start`, verify that `ssh-add -l` contains the `vde_student` identity.
- Implement a silent handshake check inside the persistent `socat` bridge.
- Transition Spoke to a "Safety-Lock" state (refuse execution) if the bridge is fractured.

## 4. BESKAR LAYER OPTIMIZATION (Docker Image Caching)
**Architecture**: Multi-stage optimization of the build strike.
**Optimizations**:
- Group common development tools in `vde-base.Dockerfile` to maximize layer caching.
- Add an "Image Purity" verification step in `vde-lang.Dockerfile`: `RUN [ $(ls /var/lib/apt/lists/ | wc -l) -eq 0 ]`.
- Adhere to Section 11 (Efficiency) by minimizing re-hydration time.

## 5. THE ARCHIVIST’S VISION (Observability Dashboard)
**Architecture**: A new CLI tool `bin/vde-vision`.
**Output**: A real-time Markdown grid showing:
- Active Spokes, Uptime, and Port Allocations.
- Diagnostic health (Handshake status).
- Version parity (1.3.0 vs Current).
- Active logs in `plans/`.

## 6. TEST-DRIVEN IMAGE HARDENING
**Architecture**: New BDD Scenarios in `@system-spine`.
**Scenarios**:
- **Image Purity**: "Then the directory /var/lib/apt/lists/ should be empty in the Spoke".
- **Bridge Integrity**: "Then the Spoke should be able to see the host SSH identity".
