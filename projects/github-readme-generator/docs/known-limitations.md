# Known limitations and acceptance status

- Preview approximates GitHub. Sanitization and unsupported HTML can change displayed output without changing exported Markdown. Themes cannot apply arbitrary CSS to GitHub.
- Complex imported Markdown remains Custom Markdown. Structured ownership detaches when raw edits cannot be synchronized safely.
- Remote badges/widgets depend on their providers, and relative image preview needs repository context. Link checks can be inconclusive because of CORS or network policy.
- Browser storage has quotas and may be cleared by private browsing or the user. Autosave is not an independent backup and crash-time flush is best effort.
- Large documents complete regression checks through 1 MB, but preview can be slow and undo history is bounded. Publishing supports UTF-8 README text up to 750 KB.
- Publishing requires an operator-configured HTTPS service, a GitHub App, installation and effective permissions. Static hosting alone provides authoring/export. Multi-process session storage is not supported.
- Asset and README writes are sequential, not atomic. A lost response may hide a completed remote write; inspect GitHub before retrying. No force-push or silent conflict overwrite is provided.
- Offline support requires successful prior caching and a browser that permits service workers. Remote fetch/publish/preview still needs connectivity; installation is optional.
- Repository audit project types are explainable suggestions with manual overrides. English prose/topics and approximate section evidence may misidentify mixed-purpose or multilingual repositories. Type expectations are advisory, and overrides last only for the current audit tab session. See [project-type rules](repository-auditing.md#project-types-111).
- Language selection is manual; Studio does not detect or translate languages. Translation review tracks exact source revisions and conservative section identities, not semantic equivalence between languages. Repeated identities and content beyond 100 sections are Unknown, and revision tracking is limited to 1 MB of UTF-8 Markdown per source. English wording and conventional-section heuristics are Unknown for non-English editions; structural, link, media and source checks remain available. See [Multilingual documentation](multilingual.md).
- Drift checks interpret commands with simple shell rules, read only the root `package.json`, one `.env` example and ten linked Markdown files, and approximate GitHub heading anchors. Observed mismatches are limited to direct contradictions; everything heuristic is labelled uncertain and unreadable evidence is unknown. See [Drift checks](drift-checks.md#limits). Reviewed drift fixes edit one line per proposal, suggest corrections only for case-only paths, near anchors, near script names and prose Node versions, and refuse to apply after any Markdown edit since the check; see [Reviewed drift fixes](drift-remediation.md#limits).
- Stack Intelligence reads root Manifests only unless Nested discovery is turned on. Nested discovery reads at most 15 nested Manifests up to four directories deep per repository and at most 25 repositories per run, skips dependency and build directories, symlinks and submodules, and interprets only simple workspace patterns. A truncated repository tree leaves unlisted Manifests unknown. Bazel/Nx/Turbo/Lerna configuration, lockfile membership and local `path =` dependencies are not followed. See [Nested discovery](stack-intelligence.md#nested-discovery-monorepos).
- Stack results are marked Stale from the loaded repository list's `pushed_at` and a 24-hour age only. Studio does not check which files a push changed, so Stale can be a false alarm, and it is not re-evaluated until the results are shown again. Confidence bases are categorical labels from the manifest format, not a measure of how a dependency is used. See [Provenance, confidence and staleness](stack-intelligence.md#provenance-confidence-and-staleness).

Release candidate automation covers three browser engines, source recovery and mocked publishing failures. Manual screen-reader acceptance, live GitHub App authentication/writes, and production deployment have **not** been certified by that automation. These remain stable-release acceptance gates, not completed checks. See the [readiness record](releases/1.0-readiness.md).
