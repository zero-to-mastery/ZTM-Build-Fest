# Editing and recovery

Markdown is canonical. Builder-owned blocks retain settings while serialization exactly matches their source. Custom Markdown is never silently converted into structured fields.

## Source-preserving raw edits

Typing in the Markdown editor changes only the Blocks your edit touches (its Edited scope). Every byte outside it stays identical, including CRLF line endings, a byte order mark, trailing whitespace, fenced code and HTML.

- Editing inside a Custom Markdown block, such as a split section, keeps that block, its section label and its source origin.
- Typing between two sections, or at the start or end of the document, adds the text to a neighbouring Custom Markdown block or to a new one. Builder, component and generated sections next to it keep their visual ownership while their own lines stay as they were. Whitespace alone, such as a blank line or a trailing space, never detaches anything.
- Editing inside an Owned block (a builder section, a component, a generated, shared or profile section, or the inserted banner) causes a Detachment: that block becomes a Custom Markdown block holding exactly what you typed. An edit that spans several blocks merges them into one Custom Markdown block. A change made in several places at once, such as drift fixes or reviewed refactors, detaches only the blocks each change touches; untouched sections between them keep their ownership. Deleting a section's last line, or an edit that reaches only the blank line before the next section, leaves that next section alone. Text that runs on from a section's last line, or onto its first line, changes that line, so it detaches that section too: for example typing " more" after a builder section's last word, typing over the line break before the next heading, or typing at the very start or end of the document right next to an Owned section. This is decided by whether the line changed, not by how the text arrived, so typing it one key at a time detaches the section exactly as pasting it would. Moving an Owned section to another place in one edit detaches it, also when the same edit changes its text, and its record sits on the Custom Markdown block that now holds its text. Such a change cannot be told apart from deleting the section and typing new text elsewhere in the same edit, so that is recorded too.
- A Detachment is never silent. A polite status message names what was detached, for example "Raw edit detached: Tech Stack (builder). Undo restores visual ownership.", without moving focus. The Sections list shows "Detached from Tech Stack" on that block.
- Each Detachment is saved as a Detachment record on the document. Records travel with Undo, autosave, draft and workspace backups and Studio projects, keep only the 20 newest entries, and never appear in exported Markdown. A record that kept the single builder or component section it replaced is Restorable. That copy of the earlier settings stays in this browser (Undo and autosave): downloads (Studio projects, draft and workspace backups) use explicit record field allowlists, keep only the record's kinds and the section names that still appear in the Markdown (a generic name such as "Builder section" replaces any other), and leave out records of sections deleted since. A detached generated section keeps only its sources and the options needed to recreate it, and only while those sources are still named in the Markdown: never its generated text or fetched snapshot, and an option that names text no longer in the Markdown (such as its heading title or chosen technologies) falls back to the default. Generated GitHub profile text whose section is gone is left empty, which still stops GitHub Autofill adding that section back. Raw-editing a Studio-owned banner drops its banner settings and generated SVG assets; Undo restores them with the earlier draft. A split section whose heading you renamed takes the new heading as its name, and loses the name when the heading is gone. So text you removed with a raw edit never travels in a Studio project or backup. Public data fetched from GitHub (the profile snapshot, repository lists and repository context) is not text you wrote: it is kept as GitHub returned it until a refresh replaces it. Generated, shared, profile and banner ownership is never restored through Ownership review; use each feature's own reviewed recreate flow.
- In the rare case the patch cannot be proven exact, the whole draft becomes one Custom Markdown block, as in earlier releases, and the message "All sections became Custom Markdown; Undo restores them." appears. Raw editing is never blocked.

Moving or removing a section keeps the spacing between the other sections. Where a moved section's last line has no line break, a blank line is added after it so it never runs into the next heading.

Raw edits work offline and never contact the network. An empty document or an edit that changes nothing creates no Detachment record.

## Ownership review

If a builder form or component customizer tries to save after that Block's source changed or detached, Studio does not overwrite the newer Markdown. Ownership review shows the current Markdown as **Original**, the form's visual output as **Proposed**, and a unified source diff. **Keep my Markdown** is focused by default; choosing it or pressing Escape changes nothing. **Use visual version** replaces only that reviewed Block, preserves the current Seam and records one Undo step.

The Sections list marks a Restorable Detachment with “Visual version available” and a **Review** button. Its saved builder or component version opens in the same review. If the draft changes while review is open, the first apply attempt changes nothing and refreshes Original and the diff; review the new comparison before choosing again. Missing, malformed, non-Restorable or duplicate-identity records are refused without changing source. A successful restore clears only the record it used. Undo restores the exact Markdown, Custom Markdown ownership and Detachment record from before the restore.

A section form's edits reach the README only when you choose **Save section** (or **Add to README** for a new section). If you choose **Export README** (also `Ctrl/Cmd+Shift+E`) or **Copy Markdown** while the open form has edits that would change the README, a dialog asks first: **Save section and export** saves the section as an ordinary step that Undo reverses, then exports; **Export without these edits** exports the saved README and leaves the form as it is; **Keep editing** returns to **Save section**. **Save Studio project**, **Download all drafts backup** and **Download draft backup** ask the same question, since they also use only saved sections. If the section's fields are invalid, the dialog says so and offers no save: continue without the edits, or **Keep editing** to return to the form's fields. If the form closes while the dialog is open (for example after a pane shortcut), its edits are gone; choosing to save then saves and exports nothing, and the notification says so. An opened form without such edits never asks.

Reorder sections with their up/down controls; drag-and-drop is not required. Undo/redo belongs to the active draft. History retains at most 80 checkpoints and an estimated 8 MB, so large documents retain fewer steps. History is not persisted across reloads. Workspace preferences and whole-workspace replacement are outside document undo.

Drafts and preferences autosave to localStorage after a short delay. Draft switching saves first, and page hide attempts a final flush. Browser termination cannot guarantee that last flush; use portable project downloads for independent copies. Failed saves are visible and must not be treated as success.

The draft menu creates, renames, duplicates and deletes drafts. After deletion focus moves to the draft selector. Dialogs return focus to their trigger; autosave and preview refresh do not move focus. App appearance follows the device color preference until you use the editor toolbar toggle to set a persistent light/dark override. The preview control can override README preview colors separately without changing source.

For a single editable document, save a [Studio project](studio-projects.md). For everything, download the all-drafts backup. Restore validates first and offers merge or confirmed replacement. Merge generates new draft IDs and numbered names, keeps every local draft and opens the backup's own active draft, so you see the work you restored; the notification names it, also when some incoming evidence snapshots did not fit the workspace limit. Restore is also one of the ways to start in [Guided start](guided-start.md), for a browser whose data was cleared. Libraries, themes and workspace preferences participate in backup.

If storage is corrupt or unavailable, preserve the original recovery download and export your temporary work before closing. **Download original recovery data** is an exact copy of everything that was stored in this browser, unchanged: unlike Studio projects and backups it still holds the earlier versions of detached sections, detached generated text and any other text you removed with a raw edit, so treat it as private. Original broken storage is not automatically overwritten. Future project schemas offer source-only recovery when readable. Truncated source strings cannot always be recovered. Clipboard denial offers selectable source; downloads use sanitized filenames.
