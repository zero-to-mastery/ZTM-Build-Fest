# v1.6.2 — Reviewed Drift Fixes

Implements story #191 (Reviewed drift remediation) with tasks #208 (drift finding to proposal workflow) and #209 (edit conflicts and no-silent-publish behavior) under epic #184 (Documentation Drift Detection).

After a drift check, **Review fixes** turns observed mismatches and uncertain findings into one proposal per Markdown line. Each proposal lists its findings with their evidence message, evidence file and Baseline annotation, shows the current line, an editable proposed line and the exact change, and has its own approval checkbox. A combined source view shows the checked Markdown beside the Markdown with only the approved changes. Unknown results and matches are never proposed.

Suggestions come only from evidence: a path's case-sensitive spelling, a punctuation-only near anchor, a single punctuation-or-case near script name and the `engines.node` minimum for a prose Node version. Other proposals start as the unchanged line for the author to edit. Suggestions are placed only on whole-word matches; an ambiguous script suggestion is not placed and says so.

Nothing is approved by default, and editing a proposed line withdraws its approval. Applying changes only approved lines, byte for byte elsewhere, and keeps each line's ending. It requires the current Markdown, document and target to be exactly those that were checked: any change since is a conflict, nothing is applied, the manual edit is kept and the stale proposals are cleared. One Undo step restores the previous Markdown. Applying makes no request and never publishes; Publish to GitHub remains a separate reviewed action. Proposals are held in the dialog only and are not saved (ADR 0003).

See [Reviewed drift fixes](../drift-remediation.md).
