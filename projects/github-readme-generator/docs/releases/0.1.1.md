# 0.1.1 — GitHub Autofill

This patch completes and stabilizes the GitHub Autofill capability on top of the v0.1.0 foundation. Its baseline is `cfcc5a8` on `main`; it does not rebuild the editor or introduce a new product area.

## Included scope

- Public identity and profile metadata, repository data, optional project/language/avatar suggestions, and static public stats.
- Preview-before-apply, undo/redo, persistence, and safe refresh that preserves custom source.
- Refresh ownership for untouched hero introductions and sample contact URLs, including removal of no-longer-public generated data.
- Canceled lookups on changed input, closed dialogs, or removed components; stale-result guards and bounded requests.
- Rejection of stale draft previews, malformed-response handling, retained partial results, and keyboard focus behavior.
- Regression coverage for security, previous drafts, JSON backup round trips, and both unit/browser workflows.
- Dedicated browser-test port (4317, configurable with `README_STUDIO_TEST_PORT`) and strict server ownership, so tests cannot silently run against another local application.

## Compatibility

Export remains ordinary Markdown/HTML. Public stats are dated snapshots; partial repository totals are labeled and are not presented as complete. No authentication or GitHub write access is added.

Storage schema version 1 remains in use. Existing drafts are not rewritten on load; added ownership records are optional. Fields from old drafts without records remain user-controlled rather than being retroactively claimed by autofill. Tests load both old-format drafts and current JSON backups, then exercise refresh, undo, and redo.

## Verification before release

Run these against the release commit:

```sh
npm ci
npm test
npm run test:browser
npm run build
```

The browser suite uses mocked GitHub responses, including missing profiles, partial repository results, canceled requests, changed usernames, and obsolete draft previews. It exercises keyboard navigation, mobile layout, autosave, export, and existing authoring workflows. Unit tests cover hostile API text, invalid URLs, malformed responses, timeout cleanup, preservation of manual edits, and backup compatibility.

Local release verification: **65 unit tests passed, 18 browser tests passed, and the production build passed**. Formatting and whitespace checks passed. The 100 KB browser fixture refreshed its preview in approximately 271 ms on the development machine; this is a local observation, not a cross-device latency guarantee.

Prepare and review the release branch/PR before tagging. A version bump in the branch is not a published GitHub Release. Do not tag or label 1.0 stability guarantees for this patch.
