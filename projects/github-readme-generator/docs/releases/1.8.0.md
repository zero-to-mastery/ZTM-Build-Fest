# v1.8.0 — Publishing Preflight

Implements story #97 (Preflight and permissions) with tasks #154 (build publishing permission preflight) and #155 (test read-only and denied workflow permissions), the first story of epic #69 (Safe GitHub Publishing and Change Review).

Every publishing review now opens in **Read-only mode**. The confirmation and publish button appear only after a Preflight for the exact current repository, branch and path passes every blocking check.

The Preflight is an explicit, read-only check of:

- the publishing service and the GitHub session;
- the GitHub App installation and its Contents permission;
- your push access and the repository's archive state;
- branch existence and path support;
- for workflows, the server opt-in plus Workflows: write.

Branch protection, rulesets and committing to the default branch are advisory warnings that never block. A **Re-check access** button and a Preflight check list show a written Pass/Warning/Fail/Unknown status for each check and announce the verdict. Before a target is chosen, **Supported path** shows Unknown instead of a misleading Fail.

Changing the target, disconnecting or reloading clears the Preflight; it is never saved. An offline or failed Preflight leaves every check Unknown, keeps Read-only mode, loads nothing and retries nothing automatically. **Load remote README** runs the Preflight and then the read as one explicit action, and a missing branch is reported instead of being loaded as a new file.

The publishing server enforces the same blocking checks before every write and refuses with the same message the dialog showed (ADR epic69-01). A GitHub 403 or 422 at write time opens **Publish on a new branch instead**; a refusal from the server's own Preflight does not, because branch creation would be refused the same way. **Publish on a new branch instead** is offered only when the server would accept it, and creating a workflow branch again requires the workflow opt-in.

The publishing guide gains a manual verification checklist for a real GitHub App. See [GitHub publishing](../github-publishing.md#preflight).
