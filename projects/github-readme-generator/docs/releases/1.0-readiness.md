## External information still needed

The production hosting URL/target has been requested. At inspection time GitHub Pages was disabled and the repository had no homepage URL. Do not guess a production destination or represent localhost as deployment acceptance.

Live authentication/write verification needs an operator-configured GitHub App and an explicitly authorized test repository. Existing browser/server tests mock upstream calls; they are not evidence of actual installation permissions or a correct reverse proxy. Manual assistive-technology acceptance cannot be inferred from role/keyboard assertions.

## Stable release sequence

Finish and commit 0.9.3; complete the remaining stable review and external acceptance; verify no known critical data-loss, token, silent-overwrite, export, recovery, accessibility or publishing blocker remains. Only then set package/lockfile to 1.0.0, update changelog and release notes, commit/tag the accepted source, deploy to the confirmed host, and verify that the live version and core workflow match.

Do not mark a gate passed merely because its documentation exists. Record commands, outcomes, tested commit and manual verification separately. No 1.1 features belong in this work.
