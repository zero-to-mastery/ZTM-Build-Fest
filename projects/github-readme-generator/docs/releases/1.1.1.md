# v1.1.1 — Project-Type Intelligence

Repository Audit now suggests one of 14 project types with a reason and uncertainty notice. Public topics, README prose and weak name hints are deterministic inputs; conflicting signals remain visible. Language and homepage alone do not imply that a package is published or a repository is a web application.

Each repository has a manual override, available before or after auditing. Changing it updates the assessment from cached facts without fetching or changing Markdown. Overrides survive fresh scans and reopening the audit in the same tab; selecting another account or reloading clears them.

Documentation profiles affect both evidence and classification. A short substantive experiment can be Basic while the same source is Minimal for a Web App. Missing topics are described as commonly useful, never universally required. Failed fetches remain Not assessed; activity and popularity never affect documentation classification.

See the [audit guide](../repository-auditing.md) for exact rules and limitations. This is English-language heuristic coverage, not semantic verification of instructions, API completeness or project quality. No dependency, package-manifest scan, remote inference, authentication or publishing behavior was added.

## Validation

Validation completed 2026-09-28:

- `npm test`: 622 tests across 39 files passed on the final code.
- Full Chromium/Firefox/WebKit matrix: 398 passed; one existing workspace restore test raced the browser's deferred native `toggle` event. The test now waits for persisted state before reloading instead of relying on event timing.
- Final audit/workspace matrix: all 27 tests passed across the three engines after that correction and the final experiment regression fix. This includes 100 repositories, keyboard/mobile overrides, session/reset behavior, Worker fallback and exact-source improvement.
- `npm run build` and `npm run report:bundle`: passed.
- `npm run test:static`: all six engine/root/subpath combinations passed, including production type inference, manual reassessment, audit Worker loading, offline reload/export and update activation.
- Changed-file formatting and `git diff --check`: passed.

A regression fixture ensures an Overview heading followed only by code or a tiny fragment cannot qualify as a substantive experiment. Suggestions show matched prose phrases rather than claiming certainty about a repository's purpose.

Main JavaScript is 440,773 bytes / 131,259 gzip. The lazy audit UI/client chunk is 26,511 / 9,648; its Worker is 60,243 / 20,397. The source cache, bounded concurrency and 25-row rendering limits are unchanged. All repository data in tests is synthetic; no developer was scanned and no GitHub content was written.
