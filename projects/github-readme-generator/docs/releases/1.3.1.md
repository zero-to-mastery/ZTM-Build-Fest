# v1.3.1 — Dependency Detection

Dependency results now normalize name, ecosystem, dependency kind and repository association across package.json, Cargo.toml, pyproject.toml, requirements.txt and go.mod. Duplicate records merge manifest/section/line evidence while different dependency kinds and repositories remain separate.

Go indirect requirements and unused/unresolved Cargo workspace declarations are excluded. Referenced workspace aliases resolve only from the same manifest and preserve the consuming dependency kind. requirements.txt entries remain explicit declarations; generated freeze files cannot prove directness without a resolved graph, and this limitation is documented.

The existing opt-in, read-only security boundary remains intact. Normalized results use bounded session caching with repository/branch isolation and explicit refresh. No dependency installation, repository execution or transitive resolution is introduced.

See [Stack Intelligence](../stack-intelligence.md). Verification is recorded before the separate release checkpoint.
