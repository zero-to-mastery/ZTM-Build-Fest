# v1.6.0 — Evidence Snapshots

Implements story #189 (Revision-aware documentation snapshots) with tasks #204 (snapshot schema) and #205 (retention, stale data and offline recovery) under epic #184 (Documentation Drift Detection). Later stories #190 and #191 are not included.

Documents with a GitHub target can capture an explicit, read-only evidence snapshot: branch head, README revision, recognised root manifests/lockfiles, relatively linked files and a local Markdown fingerprint. Only Git revisions are stored. A failed or truncated tree read produces a partial snapshot whose unknown entries are never treated as drift; head failures, offline use, cancellation and storage failures save nothing. One Baseline per document can be pinned, and a change check compares any same-target snapshot with GitHub now without saving. Snapshots whose target changed are labelled Different target.

Snapshots live in the version-1 workspace as a new optional, versioned `evidenceSnapshots` envelope (ADR 0001). They are included in workspace backup/restore/recovery, follow regenerated document IDs and are excluded from portable project schema 1, single-draft JSON and README exports. Retention keeps five snapshots per document plus its Baseline, 100 per workspace.

See [Evidence snapshots](../evidence-snapshots.md).

## Review fixes

- A capture that fails while saving (storage full, all-Baseline retention) no longer leaves the panel busy with disabled buttons and a dead Cancel.
- Merge restore never evicts local snapshots. Incoming snapshots fill the remaining space; the rest stay in the backup file and the restore message counts them.
- A fresh capture always survives retention, even behind future-dated snapshots; if every other retained snapshot is a Baseline, capture is refused instead of silently dropped.
- Recovery salvages at most 100 Baselines and never fails draft recovery because of snapshot data.
- Relative links that climb above the repository root, or whose paths cannot be decoded, are listed in snapshot notes instead of being mapped onto root files or dropped silently.
- The panel's status live region is no longer replaced on re-render, so outcomes written after a refresh can be announced (not yet confirmed with a screen reader).
- Deleting a draft states how many evidence snapshots, including a Baseline, will be deleted with it. The Workspace documents guide now covers the Evidence snapshots entry point.
