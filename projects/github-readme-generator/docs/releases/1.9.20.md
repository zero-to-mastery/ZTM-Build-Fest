# README Studio 1.9.20

Generated banner assets now have a deterministic package manifest.

- Download `readme-studio-assets.json` without changing README Source or contacting GitHub.
- Review a versioned, stable inventory of generated paths, roles, media types, UTF-8 byte sizes and content fingerprints.
- Keep the exact portable picture markup beside the inventory so every file can be traced to its exported reference.
- Reject unsafe relative paths, traversal, hidden segments, duplicate destinations, oversized files and files missing from the exported references.
- Use the same normalized package for local downloads and optional reviewed GitHub publishing.

The manifest deliberately excludes timestamps, application version, repository targets, credentials and SVG source. Its FNV-1a fingerprint is for drift detection, not authenticity. It is a download/review format, not an import format or instruction to publish.

Automated release evidence covers byte-stable serialization, path collisions and traversal, exact references, content fingerprints, source preservation, browser download behavior, the existing publishing validation path, Chromium/Firefox/WebKit interaction, production build and static smoke checks.

Manual review should generate the same package twice and compare the manifest bytes, match every listed path to a downloaded SVG and the exported Markdown, inspect each SVG before committing it, and confirm no remote action occurs until the separate Publish to GitHub review is explicitly approved.

This release completes Story #96 and tasks #152 and #153.
