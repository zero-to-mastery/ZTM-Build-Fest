# v1.1.2 — README Attention Queue

The repository audit now offers a separate attention queue with explainable High, Medium and Low tiers. Recent activity and thin documentation identify immediate candidates; archived or long-inactive repositories appear lower. Type-specific gaps are advisory. Public-interest signals break ties without numerical quality scores or developer rankings.

The queue combines priority, missing, active, archived, language, project type, minimum-star and recent-push filters. Improve next and Open in Studio use the existing exact-source/new-draft flow. Only successful assessments enter the queue, and rendering is limited to 25 items per page.

Local preferences support seven-day ignore and intentionally-minimal decisions tied to a README revision. They survive reloads, can be reviewed and reversed, and stop suppressing a changed revision when it is fetched. Failed writes are visible; malformed/future storage stays untouched with an explicit recovery/reset path.

See the [queue guide](../readme-attention-queue.md) for exact ordering, type-topic subsets, snapshot/cache limits and browser-local preference scope. Pinned/featured and release metadata are not fetched. No dependency or new network operation was added.
