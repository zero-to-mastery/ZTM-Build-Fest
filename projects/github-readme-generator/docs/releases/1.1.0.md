# v1.1.0 — Repository README Audit

The GitHub task group now includes a public repository documentation audit. It classifies selected root READMEs using explicit evidence from the existing analyzer, without quality scores or developer rankings. Repository activity and archive state are independent of documentation classification.

Public owned repositories paginate to 1,000; forks and archives are optional. Three concurrent requests, 25 rendered rows per page, bounded source caching and retained completed assessments support larger audits. Rate-limit retries resume unfinished work unless the user explicitly requests fresh content. Improve creates a new local draft and preserves exact source, including BOM/line endings. No publishing or authentication behavior was added.

## Validation — 2026-09-28

- `npm test`: 586 tests across 38 files passed on the final implementation.
- `npm run test:browser:all`: 396 tests passed across Chromium, Firefox and WebKit before the final BOM/resume refinements.
- Final audit/workspace browser matrix: 24 tests passed after those refinements, including cache expiry followed by retry of only the failed repository, 100-repository batches, 320px keyboard controls and Worker fallback.
- `npm run build` and `npm run report:bundle`: passed.
- `npm run test:static`: passed for all three engines at root and `/readme-studio/`, including the production audit module/Worker, existing offline reload/export and update activation checks.
- Unit pagination covers 1,000 records. Network responses are synthetic; the tests do not assert that unauthenticated GitHub permits 1,000 fresh README requests in one rate-limit window.

Main JavaScript is 440,817 bytes / 131,295 gzip. The audit UI/client chunk is 17,525 / 6,488; the audit Worker is 55,841 / 18,748; the fallback classifier is 3,182 / 1,654. No dependency was added. The production offline cache includes build chunks; lazy loading avoids initializing the audit UI until it is opened.

The browser review exposed a native fetch receiver bug, which was fixed and verified in real browser engines. The production audit network fixture runs before service-worker control because Playwright routing can miss service-worker requests; offline behavior remains a separate production check.

## Scope and limits

See [the audit guide](../repository-auditing.md) for the exact rules, English-language heuristics, 1 MB README cap, public API limits, root README fallback and session retention. A missing root README can coexist with documentation under `.github/` or `docs/`; evidence records that distinction. Fetch errors remain not assessed.

This version is prepared on top of the preserved release-candidate work in PR #38. It does not retroactively claim that the pending v1.0 manual authentication, assistive-technology or production-deployment gates were completed. No release tag or production deployment is part of this feature checkpoint.
