# v1.9.4 — Reviewable change sets

Implements story #98 (Reviewable change sets) with tasks #156 (reviewed change-set manifest) and #157 (per-file SHA and explicit approval tests), the second story of epic #69 (Safe GitHub Publishing).

Every GitHub publish now begins with an immutable **change-set review** for the exact owner, repository, branch and checked head commit. It lists every README, asset and workflow write with its action, path, Base SHA, Result SHA and unified diff. New files have no Base SHA; updates identify the exact Git blob that was reviewed. The review never includes a delete, forced update or ref rewrite.

Nothing is approved by default. The publisher must explicitly approve the exact manifest, and a change to Markdown, generated files, the target or any reviewed input withdraws that approval. Closing and reopening the dialog also begins unapproved. Offline and failed reads leave publishing unavailable instead of guessing at remote state.

The client rejects tampered, duplicated or incomplete manifests. Immediately before writing, it re-reads every existing target file and refuses a stale, missing or unexpectedly present file. For each submitted write, the publishing server independently validates its expected Base SHA and recomputes its Result SHA. A partial failure reports which files were written and does not retry automatically; the author must review a new change set against GitHub's updated state.

See [GitHub publishing](../github-publishing.md#change-set-review), [Architecture](../architecture.md) and [Security](../security.md#optional-github-publishing-service).
