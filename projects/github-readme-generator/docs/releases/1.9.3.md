# v1.9.3 — Explainable improvement plans

Implements story #80 (Explainable improvement plans) with tasks #124 (type-aware evidence-backed action planner) and #125 (recommendation review and false-positive tests), the first story of epic #64 (Actionable README Audit and Prioritization).

Every assessed repository in the audit and README Attention Queue now has an **Improvement plan** derived from the evidence already loaded in the tab. It makes no request, reads no README again and remains available offline. Each Recommendation comes from exactly one Audit finding, cites the observed README revision and observation or check time, and explains why it may apply to the repository's detected or manually chosen project type. It never invents replacement content, commands, URLs or repository facts.

Recommendations use descriptive **Start here**, **Next** and **Optional** bands rather than scores. Missing or thin READMEs, starter text and placeholders lead; key project-type gaps and unavailable links or images follow; secondary topics and README-history review remain optional. Plans are deterministic, use a stable order and list at most 30 Recommendations. Missing and stub READMEs are folded into one Recommendation with relevant sections to consider instead of one Recommendation per topic.

Conservative caveats reduce false positives. Topic Recommendations become Optional when the project type is only a weak inference or the README appears substantive but its headings may not use English terms. Public APIs, documentation links and Experiments have their own applicability caveats. Failed repository reads never become missing-README recommendations, and a plan with no suggestions explicitly says that it is not a quality verdict.

Each Recommendation offers the existing reviewed flows to Improve README, Open in Studio or open the README on GitHub, plus session-only **Skip** and revision-bound session-only **Dismiss** choices. A missing or thin README cannot be dismissed and instead uses the existing **Mark intentionally minimal** decision. Skip and Dismiss make no request, change no Markdown and publish nothing. When a fresh audit observes a different or unknown README revision, an earlier dismissal is shown as stale and no longer applied until the author acts again.

See [Repository auditing](../repository-auditing.md#improvement-plans) and [README Attention Queue](../readme-attention-queue.md).
