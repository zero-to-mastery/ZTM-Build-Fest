# v1.9.2 — Evidence freshness and confidence

Implements story #84 (Evidence freshness and confidence) with tasks #132 (record provenance and staleness per declaration) and #133 (implement uncertain-result UI and tests), the second story of epic #65 (Repository Evidence and Stack Intelligence).

Stack Intelligence shows the **Provenance** of every detected declaration: Manifest path, section, line, branch, shortened blob SHA and when it was observed. The full blob SHA is available to screen readers. A cached result keeps its original Observed at.

Each declaration has a named **Confidence basis** (explicit, inherited, conditional or ambiguous) with one fixed explanation. Bases are never a number or ranking and never describe skill. Poetry dependencies declared `optional = true` are conditional, like Cargo and PEP 621 optional dependencies.

Each repository result has an **Uncertain stack results (N)** list. It holds conditional and ambiguous declarations with their reason, and manifests that were found but not read, listed as "Not read — unknown". The count includes unread manifests beyond the listed paths, so it matches the discovery summary. Uncertain results still appear in place in the dependency list. The "Found, not read" heading in Project boundaries is now "Not read — unknown".

Results are marked **Stale** when the loaded repository list shows a newer push than the one the scan started from, or when they were observed more than 24 hours ago. Both push times come from GitHub, so a wrong local clock does not change the result. The text badge points to Fetch fresh manifests, and the summary line includes "Stale". This is worked out when results are shown, with no timers or extra requests.

Stack DNA evidence shows the same provenance and basis, and labels technologies with only conditional or ambiguous evidence as "only uncertain evidence". In Stack-to-README review, each evidence line names its Confidence basis. Technologies with only uncertain evidence are left out of the Detected stack section and get no badge suggestion. They are offered separately, unselected, as "Technologies with only uncertain evidence", with a caveat.

Stack scan records are now version 5 and session-only. `observedAt` replaces `checkedAt`, which remains as an alias for one release. Records gain `pushedAt`, and dependency evidence items carry full Provenance with a named Confidence basis. The basis explanation is looked up when shown and is not stored with each item. See [Stack Intelligence](../stack-intelligence.md#provenance-confidence-and-staleness).

## Not verified here

- Staleness is re-evaluated only when results are rendered again (for example on a selection change or after the repository list reloads). On purpose, per ADR epic65-02, there are no timers or auto-refresh.
- The pushed-since check uses the loaded repository list, which the audit client caches for five minutes. A push made after the list was loaded is only seen once the list is fetched again.
- Stale can be a false alarm, because a push may not touch any Manifest. Bases are categorical labels from the manifest format, not usage verification.
- Provenance includes the branch and blob SHA but not the head commit SHA; that stays on `record.headSha` in nested mode, as specified.
- The writing-assistant `stackContext` still sends `checkedAt` (an alias of `observedAt`) and was left unchanged.
- Story #85 (Evidence-to-documentation: confirmation and per-project commands) is not implemented. `readme-suggestions` still uses the Stack DNA `source` strings.
- The story issue body lists two unrelated template tasks (media asset manifest, publishing preflight) that look like copy errors; they were not implemented.
