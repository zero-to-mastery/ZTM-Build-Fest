# v1.7.0 — Guided Entry Paths

Implements story #74 (Guided entry paths) with tasks #112 (entry-state model and goal wizard) and #113 (onboarding navigation and accessibility tests) under epic #62 (Guided First-Run and Task-Based UX).

A new workspace now opens **Guided start**, which asks what the author wants to do first: **Write my profile README**, **Write a repository README** or **Audit my repository READMEs**. Each Goal has a one-line description, and the audit says it needs a GitHub connection. Choosing a Goal replaces the dialog content with a second step and moves focus to its heading. That step offers existing flows only: profile templates, Autofill from GitHub or a blank profile README; the repository README builder, Import existing README or a blank repository README; or Open README audit. **Back** returns to the Goals with focus on the chosen one. Offline, Open README audit keeps focus but is `aria-disabled` with the reason as its description, and Import existing README and a blank repository README are offered instead.

The earlier Start paths stay in **Other ways to start** under their existing accessible names, including **Import GitHub README**; step 2 of the repository and offline audit Goals names the same dialog **Import existing README**. The Locality statement, a labelled region, says that drafts stay only in this browser, are unencrypted and can be cleared, so the author should download a backup. It also says GitHub is contacted only when the author chooses a GitHub action, and names each one listed in the privacy notes (import, autofill, audit, repository lookup, refresh and link checks, evidence and drift checks, publishing); link checks also contact the linked sites; analysis runs in the browser and Markdown is sent only when the author publishes it or reviews and sends text to the optional Writing Assistant's provider; preview images and badges load from their own sites; and nothing is published without its own review. With blocked storage it says the workspace is temporary; when the saved workspace cannot be read it says the original is untouched and points to Download original recovery data. Guided start opens by itself only without a saved workspace, and not when a saved workspace cannot be read, so the recovery notice stays usable. **Create → Guided start** and workspace search reopen it, with the saved Goal marked and focused.

The Goal is stored in a new optional `guide` workspace field, `{ version: 1, goal, nextSteps }`, as ADR 0004 sets out. It lives in the pure module `src/workspace/guide.js`. The field is included in storage recovery and all-drafts backups. A replace restore uses the backup's value and a merge keeps the current one. Studio projects, single-draft JSON and README export never contain it. An earlier workspace gets the default. An unknown Goal reads as null. A `guide` that is not version 1 (another version, or a malformed value such as `null` or a string) that is at most 1 KB, and that an all-drafts backup carries unchanged (within its nesting limit and with no credential-named key such as `session`), is kept unchanged and read as no Goal; a larger or uncarriable one gets the default, so a damaged guide cannot break Download all drafts backup. Workspace version 1 and project schema 1 are unchanged. Guided start makes no request and adds no dependency or telemetry, and choosing a Goal never changes a document. Next steps (#75) and usability validation (#76) are not part of this release; the `nextSteps` flag is stored for #75 but not yet shown.

See [Guided start](../guided-start.md).

## Verification — 2026-10-22

- Unit tests: 968 across 62 files passed. They include 15 in `tests/guide.test.js`:
  - the Goal definitions, with only the audit needing the network, and the step 2 options, including the offline audit alternatives;
  - defaulting and version-1 normalization (a non-string Goal such as `["audit"]` reads as no Goal), and unchanged pass-through of small unknown or malformed values;
  - replacement of values over 1 KB or that cannot be serialized, and explicit choice as the only replacement;
  - replacement of a guide an all-drafts backup could not carry unchanged (nested past the backup limit, or with a credential-named key), so Download all drafts backup keeps working;
  - storage round-trip, and recovery from damaged storage without writing;
  - backup inclusion, with replace using the incoming guide and merge keeping the current one;
  - absence from Studio projects (with embedded libraries and stray fields), single-draft JSON, settings and README source;
  - the Guided start command.

  Removing `guide` from `validateWorkspace` makes four of them fail.

- Full Chromium browser suite: 195 passed, including nine workflows in `tests/browser/guided-start.spec.js`:
  - the first-run Goals, their descriptions, every Start path name, the Locality statement naming every GitHub-contacting flow, link checks to linked sites, the opt-in Writing Assistant as the only other way Markdown is sent, and its privacy link, with no GitHub request;
  - keyboard Goal choice at 320px with focus on the step heading, Back restoring focus, the saved Goal, no document change, no reopening after reload, and reopening from search with the current Goal marked;
  - each step option opening its existing flow, and blank profile and repository documents in the right group;
  - the offline audit staying focusable and unavailable, also when the connection returns while step 2 is open, with alternatives offered and the audit available again after reopening online;
  - blocked storage showing the temporary-workspace text, and an unreadable saved workspace skipping the automatic Guided start and pointing to its recovery data;
  - the Goal present in all-drafts backups but absent from README, draft JSON and Studio project downloads;
  - the import journey: Import existing README from the repository Goal and Import GitHub README from Other ways to start each load a synthetic local file, preview it without changing drafts and import it as a new draft, with no GitHub request;
  - the offline audit fallback Import existing README importing a local file while offline (on WebKit, whose Playwright offline emulation also fails local file reads, the fallback is reached offline and the file is read back online);
  - Explore the sample profile closing on first run and adding a profile copy when Guided start is reopened.

  Removing the offline guard, or allowing activation once the browser is back online, makes the offline workflow fail. The existing specs that use the Start path names pass unchanged.

- Full Firefox and WebKit browser suites: 195 passed each, as `test:browser:all` runs them in CI on release branches.

- Production build and six root/subpath static/offline smoke checks passed (Chromium, Firefox and WebKit). Main JavaScript is 498.05 kB (149.06 kB gzip). No new dependency. Formatting passed.
