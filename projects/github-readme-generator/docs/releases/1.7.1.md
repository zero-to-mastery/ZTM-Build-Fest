# v1.7.1 — Contextual Action Flows

Implements story #75 (Contextual action flows) with tasks #114 (context-sensitive next-action recommendations) and #115 (flow transitions and focus states) under epic #62 (Guided First-Run and Task-Based UX).

After an Arrival (an import, a README opened from the audit, a template or a blank start), a **Next steps** panel above the workspace panes suggests at most three existing tools, each with a one-line reason, and one sentence about what happened, such as "Imported into a new local draft. Nothing changed on GitHub." **All tools** opens workspace search so every other control stays one step away, and **Hide** removes the panel.

Arrivals are recorded for:

- `import-apply` in every mode, including Re-import (origin GitHub or file);
- a Studio project opened as a new draft (an import from a project);
- the README audit's Improve README, whether it opens an existing document, a new draft or the repository builder;
- a profile template, or the repository README builder outside the audit (its open-original action counts as a GitHub import);
- Guided start's blank options.

The Arrival lives in memory only (ADR 0005). Hide, a document switch, a workspace restore, a new Arrival, undoing a replace, append or merge import past its change, or a reload forgets it, and it is never written to storage, backups or projects.

The steps come from the pure rule `nextSteps(arrival, facts)` in `src/workspace/guide.js`. The facts are cheap: block count, a single Custom Markdown block, empty Markdown, repository target, document group, import source, Goal, online state and blocked storage (blocked at startup, or a save that failed later, such as a full quota). The rule runs no Health or drift analysis and makes no request. It only offers existing command or `data-action` ids plus the Sections and Library builder tabs, and never offers publishing or a write. The table:

| Arrival                                 | Next steps                                                                                  |
| --------------------------------------- | ------------------------------------------------------------------------------------------- |
| Profile template                        | Edit your sections · Autofill from GitHub · Preview README                                  |
| Repository template                     | Replace writing prompts · README Health · Set repository target, or Preview README once set |
| Import new/replace, one Markdown block  | Split into sections · README Health · Drift check with a target, else Preview README        |
| Import new/replace, structured or empty | Preview README · README Health · Drift check with a target, else Compatibility Lab          |
| Import append/merge                     | Preview README · README Health · Compatibility Lab                                          |
| Audit                                   | README Health · Drift check (only with a target) · README Attention Queue                   |
| Blank                                   | Add a section · Start from a template · Import existing README                              |

Offline, steps that read GitHub are removed and the panel says "GitHub steps are hidden while offline." With blocked storage, or after a save fails, the last step becomes Export README.

Each step is a button with the same `data-action` as the visible tool, so stale-draft guards, review dialogs and Undo stay with the tool. The panel is a labelled region, not a live region; each Arrival's own notification announces what happened (profile templates now say "<name> template opened as a new local draft." and blank starts "Blank draft created."). It never moves focus and is inert behind dialogs through native modality. When a step's dialog closes, focus returns to the step. Steps are recomputed when a dialog closes, after Undo or Redo, and when connectivity changes, and they are keyed by command so a kept step keeps its button; when a step is replaced, for example Set repository target by Preview README once a target is saved, focus and the dialog's return target move to the step now in its place. Hide focuses the editor when it is visible, otherwise Current draft. **Save → Settings → Guidance → Show next steps after imports, audits and templates** stores `guide.nextSteps` (ADR 0004); when it is off, the panel never shows.

Two existing browser specs now scope a locator, because the page can show the same tool name twice when the panel offers it: `import.spec.js` clicks the builder's **Split into sections**, and `workspace-documents.spec.js` clicks **README Health** in Workspace tools.

- Unit tests: 979 across 63 files passed. They include 11 in `tests/next-steps.test.js`:
  - Arrival normalization (unknown detail values dropped, a document and a known kind required);
  - the whole rules table as an explicit snapshot, including targets, block shapes, empty imports and the template fallback from document group to Goal;
  - the offline filter and its "hidden while offline" flag, and Export README as the last step with blocked storage;
  - a sweep of all 38,400 combinations of Arrival and facts: at most three unique steps, only allowed commands, never a write, publish or (offline) GitHub command;
  - the context sentences, `documentFacts` and the Next steps preference as an explicit choice.
- Full Chromium browser suite: 211 passed, including 14 workflows in `tests/browser/next-steps.spec.js` (GitHub mocked wherever a flow reads it):
  - no panel before an Arrival; a profile template shows its steps without moving focus, with no live region but its notification announced, and nothing about the Arrival is stored;
  - keyboard only: import a local README, reach Split into sections with Shift+Tab, Escape back to the step, apply the split, steps updated, and the tool's Undo and Redo restoring the block shape with the steps following;
  - undoing a replacing import removes the panel that described it;
  - a save failing after startup (quota) makes the last step Export README;
  - a step's dialog returning focus to the step, Hide focusing the editor, and a draft switch or reload clearing the panel;
  - GitHub import (Split, Health, Drift check) and Re-import merge (Preview, Health, Compatibility Lab);
  - an audit Arrival on a targeted document (Health, Drift check, Attention Queue) and returning focus from the queue; the no-target branch is fixed by the unit rules table;
  - a blank start from Guided start, its notification, and its Add a section and Import existing README steps;
  - offline filtering with the notice, and the steps returning online;
  - the Settings checkbox turning the panel off, persisting in `guide.nextSteps` across reload and back on;
  - 375px: the panel above the pane tabs, no horizontal scroll, 44px targets, Hide focusing Current draft;
  - a Studio project opened as a new draft, and a workspace restore clearing the panel;
  - a repository template whose Set repository target step, once the target is saved, is replaced by Preview README, which receives the returning focus.
- Production build passed; main JavaScript is 507.03 kB (151.98 kB gzip), within the 550 kB budget. Six root/subpath static/offline smoke checks passed (Chromium, Firefox and WebKit). No new dependency. Formatting passed.
