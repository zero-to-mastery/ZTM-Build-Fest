# v1.9.0 — Monorepo-aware manifest mapping

Implements story #83 (Monorepo-aware manifest mapping) with tasks #130 (implement bounded monorepo discovery) and #131 (test workspace boundaries and malicious paths), the first story of epic #65 (Repository Evidence and Stack Intelligence).

Stack Intelligence gains a separate, session-only **Include nested manifests (monorepo)** consent. With it, each repository is read from one tree listing at its head commit, and every file is read at that commit. The repository audit screen shows the new checkbox.

Manifests are mapped to **Project boundaries**:

- the repository root;
- **Workspace members**, declared by package.json `workspaces`, `pnpm-workspace.yaml`, Cargo `[workspace]`, `go.work` or `[tool.uv.workspace]`;
- **Nested projects**, which hold a Manifest but are not declared by a workspace.

Results list the boundaries, a "found / read / not read" summary and dependencies grouped per boundary.

Nested discovery is bounded: at most 4 directory levels, dependency and build directories skipped, at most 15 nested Manifests read per repository (members first, deterministic order), at most 24 requests per repository and at most 25 repositories per nested run. A larger selection is refused with an explanation rather than truncated. If GitHub truncates the tree, root Manifests and workspace declaration files are still found through the root listing, within the same 24-request budget.

Traversal, absolute, backslash, percent-encoded dot, control-character and over-long paths are rejected with notices. Symlinks, submodules, missing declared members and nested Manifests over 256 KB are never fetched. Workspace patterns that cannot be interpreted are reported, and matching takes bounded time for any pattern. Contents responses are checked for path, size, target and encoding.

The stack scan record is now version 4 (session-only). Manifests carry their full `path`, registry `file` and `project`, dependencies merge per Project boundary, and the cache separates nested and root-only results. Root-only analysis keeps its budget of one listing plus five Manifests. See [Stack Intelligence](../stack-intelligence.md#nested-discovery-monorepos).

## Not verified here

- Two decisions go slightly beyond the brief and are documented, not added to the ADR. Reaching the 15-read cap or the depth limit adds a notice, so the record becomes partial and is not cached; excluded directories such as `node_modules` are only listed. `*` also matches inside a single segment (for example `apps/app-*`).
- Skipped lists and per-path notices are bounded: at most 50 entries per reason bucket and 20 per-path notices. Above that, exact counts are kept and a "N more ... not listed" notice is added, so a hostile tree cannot flood the record.
- Until #85, Stack-to-README suggestions use root Manifests only. Nested and member Manifests feed the Stack DNA and technology summary but produce no commands or package links.
