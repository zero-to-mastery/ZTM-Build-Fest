# v1.1.3 — Repository Audit Hardening

The audit cycle closes with conservative placeholder/template observations, optional README history and link/image checks, bounded transient retries, rate-limit cooldown and explicit partial-result counts. Findings are advisory and can appear in the attention queue; classifications and exported source remain unchanged.

History and link checks are an explicit per-repository action. Sustained recent commits after an old observed README update can suggest a review, never prove stale documentation. Only observed HTTP 404/410 resources are described as unavailable. CORS and other unverifiable results remain separate. See [audit hardening](../audit-hardening.md) for thresholds, privacy, cache/scale limits and recovery.
