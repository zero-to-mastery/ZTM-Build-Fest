# v1.9.1 — Usability validation

Implements story #76 (Usability validation) with tasks #116 (write usability task scripts and baseline findings) and #117 (resolve priority usability defects), the last story of epic #62 (Guided First-Run and Task-Based UX).

**No usability sessions with real people have been run yet.** This release adds the scripts, the facilitator protocol and scripted Playwright runs. The Friction tracker's Participant sessions section says "None recorded".

[Usability scripts](../usability-scripts.md) define seven Usability scenarios: N1–N4 for novices and E1–E3 for experienced authors. Each has a start state, a success criterion and a step budget. The doc also has a facilitator protocol, consent and privacy statements, and a severity scale. There are no in-app analytics, telemetry or new storage (ADR 0006).

The [Friction tracker](../usability-findings.md) keeps scripted run, heuristic walkthrough and Participant session findings in separate sections.

Scripted runs (`tests/browser/usability-scenarios.spec.js`) count author actions in each scenario and attach a JSON result. They fail when a scenario stops completing or goes over the step budget in the scripts doc, and the E2 run also fails if any write request reaches GitHub. `tests/usability.test.js` checks that the scripts doc and tracker stay consistent, including findings tables placed under any other heading.

Fixes from the findings:

- Guided start offers **Restore a backup** among its other ways to start. It opens the existing restore dialog, which checks the file before anything changes.
- A merge restore of a workspace backup now opens the backup's active draft and says which draft it opened, also when some incoming evidence snapshots did not fit the workspace limit. Every local draft is kept.
- **Export README**, **Copy Markdown**, **Save Studio project**, **Download all drafts backup** and **Download draft backup** no longer silently leave out section edits that have not been saved. They ask first: save the section and continue, continue without the edits, or keep editing. Saving happens only on that choice and Undo reverses it. If the section's fields are invalid, no save is offered and Keep editing returns to the form's fields. If the form closes while the question is open, nothing is saved or exported and a notification says so.
