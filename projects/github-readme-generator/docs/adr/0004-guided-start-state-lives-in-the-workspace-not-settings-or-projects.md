# Guided start state lives in the workspace, not in settings or portable projects

The chosen Goal and the Next steps on/off preference are a new optional, versioned `guide` field of the existing version-1 workspace envelope. They are not workspace settings, because `workspaceSettings` is copied into every portable Studio project and "Use saved workspace preferences" would let a shared project overwrite another author's Goal. They do not get their own storage key either, because a separate key would ignore workspace restore and recovery. Like `activity`, the field joins all-drafts backups and storage recovery, while portable projects, single-draft JSON and README export leave it out, so project schema version 1 and the workspace version stay unchanged. A replace restore uses the backup's value and a merge keeps the current one. A `guide` of an unknown version or a malformed one (any value that is not a version-1 object), up to 1 KB and passing the all-drafts backup boundary unchanged (nesting limit, no credential-named keys), is kept as it is and treated as "no Goal" until the author chooses again. We accepted that a Goal does not travel between machines except through a full backup.

Guided start opens by itself only when the browser has no saved workspace. A saved Goal never sends a returning author into a dialog. It only marks the current choice when Guided start is reopened and selects the Next steps (ADR 0005).
