# Audit decisions use a new storage key and read the old attention key without rewriting it

Implemented in v1.9.9.

Persisting Manual project types and Dismissals next to the existing Ignore for now and Intentionally minimal decisions needs a wider schema than the version-1 envelope in `readme-studio:attention:v1`. We considered writing a version-2 envelope into that key. However, the service worker lets an older app version stay open in another tab. That tab would report the newer data as damaged and offer a reset that discards it. Instead, all Audit decisions move to a new key, `readme-studio:audit-decisions:v1`, which holds its own inner `version: 1`. While the new key is absent, the valid legacy key is read and converted in memory. The first successful write saves the converted decisions with the new one. The legacy key is never written, migrated in place or deleted by the new code. Damaged legacy data blocks new writes until the author downloads it or explicitly starts fresh, so a damaged legacy key is never silently dropped.

Like the attention key, the new key stays outside all-drafts backups, portable projects and README exports. It has its own recovery download and explicit reset, and holds only Canonical repositories, project type IDs, Observed revisions, finding identities, decision kinds and expiry times. We accepted that decisions do not travel between browsers, and that a decision made later in an old-version tab never reaches the new key. In return no migration is destructive, an old tab cannot erase newer data, and draft storage and backup formats stay unchanged.
