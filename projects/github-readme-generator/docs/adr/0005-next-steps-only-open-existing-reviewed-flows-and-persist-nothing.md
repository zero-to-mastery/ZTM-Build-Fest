# Next steps only open existing reviewed flows and persist nothing

After an import, an audit, a template or a blank start, the Next steps panel suggests at most three existing commands, chosen by a pure, deterministic rule from the Arrival, the Goal and cheap facts about the document (block shape, target, import source). It also checks whether the browser is online and whether storage is blocked. It never runs Health or drift analysis, fetches anything, applies a change or suggests publishing. Each step dispatches the same `data-action` as the visible tool, so stale-draft guards, review dialogs and Undo stay owned by that tool. We rejected one-click "do it for me" steps and steps ranked by background analysis. Both would add a second, unreviewed way to change Source and would make suggestions depend on worker timing.

The Arrival lives only in memory for the active document. It is cleared by a document switch, a workspace restore, a reload or Hide, and is never written to storage, backups or projects. Only the workspace-level Next steps on/off preference is saved (ADR 0004). We accepted that a reload drops the panel, in exchange for no per-document guidance metadata that would need migration, merging and recovery.
