# Raw edits detach only the Blocks they touch

Today any raw edit turns the whole draft into one Custom Markdown block, so typing one character in the Preamble drops the settings of every builder section, component and generated section. From Epic 02 on, `Store.raw` works out the one changed range by comparing the old and new Source from both ends (common prefix and suffix, widened so it never splits a `\r\n` pair or a surrogate pair). It then maps that range onto the Blocks' source ranges (`documentSegments`) and replaces only the touched Blocks. One Custom Markdown block that was touched keeps its ID. Touched Owned blocks are merged into a single new Custom Markdown block with a new ID, so a builder form left open on the old ID can no longer overwrite them. Text inserted at a Seam goes into an adjacent Custom Markdown block, or into a new one, and never detaches a neighbour.

We considered a full Markdown diff per Block, and re-parsing edited text back into builder settings. The first costs more on every keystroke and still needs a fallback. The second would silently turn the author's text into settings, which the editing guarantees forbid.

The result must satisfy `serializeBlocks(blocks) === markdown`. If it does not, or anything throws, the old whole-draft behaviour is used. Raw editing is never blocked.

Seams belong to positions. Moving or removing a Block keeps each position's separator. Where a Block's text does not end in a line break and the next Seam is empty, that Seam becomes a blank line. The Seam lies inside the move's Edited scope, so no bytes outside the edit change.

Refinements found while implementing #77. An edit that stays inside one Seam and leaves only whitespace there changes that Seam alone, so adding or removing a blank line between two builder sections detaches neither. Text typed at a Seam after a non-custom Block goes into the following Custom Markdown block when there is one, and otherwise into a new Block. A pure deletion is ambiguous when the removed text repeats around it (deleting "\n\n## B" before "\n\n## C" also reads as deleting "## B\n\n"), so it is slid left, at most 64 characters, onto a Block boundary; deleting a whole section then removes that Block and its Seam without touching the next one, and leaves no empty Block and no record. Removing a Block through the Sections list removes its own Seam, so no other Seam's bytes change.

Typing exactly at the end of a Block's text, or exactly at the start of the next Block's text, edits that Block, so appending to a builder section's last line detaches it rather than leaving the new words in a separate Block. Only text typed strictly inside a Seam (for example on the blank line between two sections) is a Seam insertion. Where a Seam is empty, a neighbouring Custom Markdown block takes the text first. Insertions at the very start or end of the document follow the Seam rule, as decided above.

Review of #77 added two more. A source edit can change several places at once (drift fixes, reviewed refactors, the writing assistant). The one changed range is split around every Block whose text reappears unchanged inside the replacement, and each remaining range is patched on its own, right to left, so untouched Blocks between the changes keep their ownership. If any step cannot stay exact, the single-range patch is used. A range that reaches only the next Block's Seam, such as deleting a section's last line with its line break, leaves that Block's text, and so its ownership, alone: the Block is kept and its Seam becomes the whitespace before its text, provided the text still starts on its own line.

Verification of #77 added two more. The editor runs `Store.raw` on every keystroke, so a rule about edit shapes is not enough: typing " more" after a builder section puts the space in the Seam (a whitespace-only Seam edit) and each letter after it inside the Seam. So ownership is decided by lines, not edit size: after every patch, an Owned block that kept its ID must still have the same non-whitespace text before its first line and after its last line. If it does not (text typed on its line through a Seam, or at the very start or end of the document), it is merged with every Block that now shares that line into one Custom Markdown block with a Detachment record, the same result as pasting the text in one edit. Text typed inside a Seam that runs on from an Owned block's last line edits that Block directly. A multi-place edit can move an Owned block and change its text at once; a dropped Owned block is then recorded on the Custom Markdown block that gained an exact copy of it, else most of its lines, else most text. Only when no Custom Markdown block gained anything is it a plain deletion with no record.
