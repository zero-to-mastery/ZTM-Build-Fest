# Improvement plans are derived from audit results and cite only observed evidence

An Improvement plan is a pure function of one repository's in-session audit record (classification, project type, placeholder/starter/history/link findings) and the author's Audit decisions. It is recalculated whenever those change and is never saved, so it cannot age, needs no schema and adds no network request. Each Recommendation maps to exactly one Audit finding, quotes what was observed (counts, the heading terms looked for, the link URL and HTTP outcome, the README revision and when it was read) and states its Applicability. It never contains proposed README text, commands, URLs or facts the audit did not see. Its only actions open existing reviewed flows: Improve README (the repository builder), Open in Studio, Open README on GitHub, and the existing queue decisions. A failed fetch produces no plan at all, never a "missing README" plan.

Audit findings get stable string identities (for example `topic:installation`, `starter:vite`, `link:unavailable:fnv1a32:…`) instead of the free-text messages they carry today. Dismissals (Story 03.2) and Audit snapshots (Story 03.3) store those identities, so renaming or removing one is a breaking change to two persisted formats. New identities may be added freely.

We rejected generating suggested section text or a ranked score. Generated text would be an unreviewed second authoring path, and a score would contradict the audit's "evidence, not scores" promise. Bands (Start here, Next, Optional) are fixed by finding kind and Applicability, not by weights.
