# Nested discovery reads one tree listing and maps declared members

Monorepo support finds nested Manifests from one recursive tree listing of the scanned branch (the same `readTree` read that drift and Evidence Snapshots use), not by listing directories that workspace globs point at. It runs only when the author turns on a second, session-only **Include nested manifests** consent next to the existing manifest consent, and it has fixed Discovery limits: at most four directory levels below the root, excluded directories (`node_modules`, `vendor`, `dist`, `build`, `out`, `target`, `testdata`, `fixtures`, `__fixtures__`, `third_party` and any directory whose name starts with `.`), at most 15 nested Manifests read per repository and at most 25 repositories per run. Workspace declarations are read as data from root files only and decide whether a Project boundary is a Workspace member or a Nested project. They never add paths that are not in the tree listing, so a declared path that is missing, a symlink (mode `120000`), a submodule or outside the root is reported, never fetched.

We rejected glob-driven directory listing because its request count grows with the pattern and the repository, which would break the existing per-repository request budget and GitHub's unauthenticated rate limit. We rejected mapping only declared members because many polyglot repositories have no Workspace declaration. We rejected treating every nested Manifest as a member because examples and tools would then look like part of the product. We accepted that a truncated tree gives an incomplete discovery, which is labeled partial, in exchange for a fixed cost of at most 24 requests per repository: the branch head, the tree, up to five root Manifests, up to two workspace declaration files and up to 15 nested Manifests.

## Consequences

- Stack results stay session-only and are not added to backups, portable projects or Evidence Snapshots. The scan record version goes from 3 to 4, and the cache key includes whether nested discovery was on.
- The `manifests` registry in `manifests.js` stays root file names only, because `github/evidence.js` builds Evidence files from it. `pnpm-workspace.yaml` and `go.work` are separate workspace declaration files, read only during Nested discovery.
