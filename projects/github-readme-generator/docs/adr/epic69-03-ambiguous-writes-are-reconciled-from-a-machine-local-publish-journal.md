# Ambiguous writes are reconciled from a machine-local Publish journal, never retried blindly

> **Status: accepted and implemented by story #99 in v1.9.6.** Story #98 added Result SHAs: each write names one, and the server refuses content that does not match it (ADR epic69-02). Story #99 adds the Publish journal, the `unknown` Write outcome, Reconciliation, explicit retry and the server's "already applied" refusal.

Before the first write of a Publish attempt, Studio saves a Publish journal to its own browser key, `readme-studio-publish-journal-v1`, separate from `readme-studio-publishing-v1` history. The journal holds the target, the Change set identity and each File change's path, kind, action, Base SHA, Result SHA, byte count and Write outcome. If the journal cannot be saved, nothing is written. A request whose answer is lost is marked `unknown`, and the attempt stops there. A journal entry still `pending` when the page loads is also treated as `unknown`. Reconciliation is an explicit read: Result SHA means `written` (recorded in history as reconciled), Base SHA or absence means `not written`, and anything else means diverged, which sends the author back to a fresh review. Retrying is a separate explicit action. It is allowed only within the same session for the same Change set, only for File changes that are `not written`, and only after Publish approval is given again. The server also refuses to write a file that already has its Result SHA and reports it as already applied, so even a duplicate request cannot write twice.

The journal stores no file content, so after a reload it supports Reconciliation and history recording but not retry; retrying then means loading and reviewing a new Change set. Like Evidence Snapshots (ADR 0001), it is machine-local: it is excluded from workspace backups, portable data and Studio projects. A malformed journal is preserved and blocks publishing until the author downloads and clears it explicitly. We rejected automatic retry with backoff, because a lost answer to a PUT often means it succeeded. We rejected bumping the history key to version 2, because existing readers reject unknown versions. We rejected keeping recovery state in memory only, because a closed tab mid-write would leave no way to tell what happened.
