# Privacy

README Studio's core editor is local-first. Markdown rendering, section building, analysis, refactors and local exports run in the browser. There is no application analytics service or cloud draft account in this repository.

Audience review is a local, in-memory analysis of the active Markdown. It does not send source or findings, persist a persona or project type, or contact GitHub. Closing the dialog discards its results and proposed order. Applying an explicitly approved order uses normal local draft history and never publishes it.

## Voluntary local feedback

**Local feedback export** is off until you open it and check its opt-in box. Opening or closing the tool creates no report and stores no preference, response or event. After opt-in, Studio builds a preview in tab memory from the app version, online/storage/reduced-motion states, coarse workspace count buckets and the answers you select. The tool accepts no free text and its strict allowlist never includes Markdown, draft names, repository names, browser identifiers, URLs, credentials or raw counts.

Choosing **Download redacted diagnostic** creates a local JSON file. Studio does not upload it, choose a recipient or remember that it exists. Sharing that downloaded file is a separate action under your control. This is distinct from the bounded Local activity list: the feedback tool is deliberately excluded from that list so merely opening it leaves no persistent feedback trace.

## Stored in this browser

Drafts, builder metadata, public GitHub snapshots, reusable badge collections, themes, snippets, favorites, recent choices and workspace preferences use browser storage. Localized document metadata stores a declared locale, linked local source-document ID, a SHA-256 source digest, and at most 100 opaque section-identity digests, order positions, ambiguity flags and section digests; removed heading text is not retained in this metadata. It is included with the document in backups and Studio projects but never in ordinary Markdown export. The optional local activity list stores bounded command identifiers and timestamps, not source or search terms. The [Guided start](guided-start.md) goal and [Next steps](next-steps.md) preference are stored with the workspace and included in all-drafts backups, but not in Studio projects or exports. Which Next steps panel is showing is kept in memory only and never stored. Publishing recovery keeps a local pre-publish source checkpoint and a bounded list of non-secret commit references. Evidence snapshots store repository paths, Git revisions, capture times and a fingerprint of your Markdown, never repository file content; they are included in all-drafts backups but not in Studio projects. Optional Audit snapshots store bounded canonical repository, revision, time, state, type, check-coverage and finding identities (plus already-observed unavailable URLs), never README source, evidence prose or decisions; their separate local key is excluded from drafts, backups, projects and exports. Learning studio progress uses another separate, versioned local key containing at most 50 records of local document IDs, project types, completed checklist IDs and update times; it contains no README text and is excluded from drafts, backups, Studio projects and exports. Download its ordinary Markdown checklist before clearing browser site data when you need a portable copy; browser site-data controls remove the stored progress.

Browser storage is not encrypted by Studio. Other users or software with access to the browser profile may read it. Download backups before clearing site data, changing devices or relying on private-browsing persistence. Portable exports contain the source and metadata you choose to include; treat them as documents that may contain personal information. Text you remove with a raw edit is not kept in Studio projects or backups (draft and all-drafts): Detachment records and detached generated sources use explicit field allowlists; records carry only kinds and section names that still appear in the Markdown (a generic name such as "Builder section" replaces any other); records of sections you have since deleted are left out; detached generated sources keep only sources still named in the Markdown and the options needed to recreate them (never the generated text, label or fetched snapshot, and never a title, technology or workflow name that is no longer in the Markdown); generated GitHub profile text whose section is gone is left empty; raw-editing a Studio-owned banner drops its settings and generated SVG assets; split sections whose heading you edited away lose that name; and the earlier draft used for Undo stays in this browser. Public data fetched from GitHub (the profile snapshot, repository lists and repository context) is a separate record of what GitHub returned: it is kept as fetched even after you delete the sections made from it, until a refresh replaces it. **Download original recovery data**, offered only when saved storage cannot be read, is the exception: it is a verbatim copy of everything stored in this browser, including those earlier settings and any text removed by raw edits.

## Network requests

- GitHub import, autofill, repository lookup and explicit refresh/link checks contact GitHub or the requested public endpoint and use the identifiers you provide.
- Evidence snapshot capture and change checks send the document's repository and branch to the public GitHub API (latest commit and repository tree), without credentials. Your Markdown is not sent.
- Drift checks send the same requests plus blob requests for at most the root `package.json`, one `.env` example and 10 linked Markdown files. Their content is parsed in memory for the comparison and discarded; neither content nor results are stored. Your Markdown is not sent, and a document with only in-page anchors is checked without any request. Reviewing and applying drift fixes makes no request; proposals and approvals stay in the open dialog and are not stored.
- Remote images, badges and widget previews contact their providers. The URL, URL parameters and your network address are visible to that provider. Studio does not proxy those requests or send the full draft as an analysis request.
- Clicking external links opens their sites. Their own privacy policies apply.
- Optional GitHub publishing sends the specifically reviewed file content and target to the same-origin publishing server and GitHub. Authentication credentials stay in that server's temporary session memory. Closing or clearing the browser alone is not a substitute for revoking an App grant on GitHub.

Generated workflow commands run only if you commit and run them on GitHub; their third-party actions have separate permissions and network behavior. Inspect them and their upstream documentation.

## Your control

Core authoring works without signing in. Network-dependent features may be unavailable offline; remote media can fail while editing and export remain usable. Clear local activity from its dialog, disconnect publishing from its dialog, export your documents, and use browser site-data controls to remove local data. The optional deployment host may keep access logs independently of this code; ask its operator about retention.

## Optional Writing Assistant

Writing assistance is off until you configure an endpoint/model, confirm the displayed content and choose Generate. The request sends the selected Original, optional notes, explicitly checked context and the chosen editing instructions to that endpoint; the API key is an Authorization header. Other drafts, unchecked repository metadata and editing history are not sent. The exact messages are displayed before sending; every optional context source starts unchecked. Connections are held in tab memory, not browser storage, projects, backups or exports; Forget connection or reload clears them. Changing the endpoint clears the key.

Provider processing, retention and billing depend on your chosen service. The request asks not to store the completion, but Studio cannot guarantee provider policy. Browser network tools and extensions can still access a key used by the page. Use a trusted local endpoint or an operator-controlled gateway for shared deployments; never bundle an operator secret into a public site. No connection test, model-list fetch, background generation or automatic retry occurs. See [Writing Assistant](writing-assistant.md).

Comparison mode explicitly requests up to three sequential alternatives from the same provider using the same reviewed content/context. All three message sets are previewed; each may incur provider charges. A failure or cancellation stops remaining requests. Completed responses stay in dialog memory and do not become draft content until reviewed Apply.

### Provider choice (1.4.3)

The writing assistant displays the selected adapter, destination, key policy and exact messages before consent. The local adapter only accepts loopback destinations and never sends an API key. No-AI mode makes no writing requests; manual editing and review remain usable. Switching providers clears the key and consent and cancels pending work. Provider settings are never imported from a repository or project file. Portable JSON and backups also strip recognized credential fields recursively; Markdown source remains verbatim, including any secrets a user manually types into it.
