# Task tutorials

## Practice README writing without changing source automatically

Open **Review → Learning studio** and choose Profile, CLI, Library, API, or Game. Read the evidence state and explanation for each guided task. **Practice in Markdown editor** selects a matching heading when exactly one is observed; otherwise it opens at the end so you can decide what belongs there. Skip any lesson, compare the synthetic annotated examples, and mark only checklist items you have verified. Download the checklist as ordinary Markdown when you want a portable copy. Learning studio never inserts or publishes text. See [Learning studio](learning-studio.md).

## Build your first profile README

Choose a template, edit the hero and About fields, then add skills through Badge Studio or Stack. Add contact links with meaningful labels. Check Preview at desktop and mobile widths and review Health. Save a Studio project before downloading README. Put the README in your profile repository yourself or use reviewed publishing.

## Import and improve an existing README

Import a file or public GitHub README as a new draft. Compare imported text before applying. Split sections if useful; raw source stays available. Open Health and Safe refactors, select one change, review before/after source and apply. Undo if it changes more than intended. Download and compare the exported README with your original.

## Create a project showcase

Open Project Studio, add a project manually or review public repository suggestions. Describe your role and specific highlights; imported repository descriptions do not replace your explanation. Choose a layout, check mobile wrapping and meaningful screenshot alt text, then save into the selected section. Save reusable project packs separately from the document.

## Build light/dark badges and a banner

Choose a theme, open Badge Studio and use theme defaults or explicit colors. Configure the light/dark pair and inspect its picture markup. Open Banner Builder, edit text and seed, then download both SVG variants. Commit assets at the paths used in generated picture markup. Preview both modes; changing Studio colors cannot recolor GitHub's page.

## Add dynamic widgets

Open Widget Hub, choose an attributed provider and read its setup requirements. Metrics and Snake may need an upstream workflow; Studio does not provision it automatically. Paste the resulting image URLs, set meaningful alt text and optional light/dark variants. Inspect source before insertion. Requesting remote preview contacts its provider, and a failed image does not block export.

## Publish safely to GitHub

First configure the optional publishing service and GitHub App. Connect intentionally; choose repository, branch and path. Load the remote file, review the exact source diff and commit message, then confirm the named target. If stale, review conflicts and the final merged source again. Asset commits precede README changes and are not atomic; check partial results before retrying. Workflow publishing requires separate permissions. Keep a local project or backup; after a lost network response check GitHub before retrying. See [publishing](github-publishing.md), [assets](assets.md) and [workflows](workflows.md).
