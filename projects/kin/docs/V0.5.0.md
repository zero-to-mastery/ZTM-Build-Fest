## Objective, scope and non-goals

Lightweight, temporary context about the capacity I have right now. Choose a fixed value and duration, set, replace or clear. No text field, journal, custom labels, scores, rankings, diagnosis, interpretation, advice, acknowledgement/read receipts, history UI, analytics, AI, notifications, identity profiles, or automatic changes to Today, Needs, Handoff or Talk. No new runtime dependency. Humans decide what context means.

## Values, actors and lifecycle

Rust PulseValue identifiers: 0 Good, 1 Okay, 2 Drained, 3 RoughDay (display “Rough day”), 4 NeedQuiet (display “Need quiet”). Pulse numeric codes are identifiers, not scores, rankings, severity levels, or quantities. UI displays labels only.

HouseholdState adds pulses ordered by opaque actor ID bytes. Each PulseState has actor_id, value, set_at, expires_at and Active/Expired status. No PulseId. Actor placeholders remain unverified; UI shows only the installation actor's “Pulse” / “Current capacity”, never actor IDs, names or a claimed partner. Future identity can map onto existing actor keys.

SET replaces only its envelope actor's current record, even if expired. CLEAR removes only that actor's record; clearing absent state is a valid no-op. SET/CLEAR/SET is valid. Exact duplicate delivery is ignored; conflicting event ID reuse fails. Local logical order, not timestamps, selects the latest SET. Expired latest records remain projected until replaced or cleared, without a history screen.

## Events and timestamps

Existing codes 1–11 and all persisted bytes remain unchanged. New schema-1 codes:

| Code | Kind          | Exact payload (little-endian)                                                      |
| ---- | ------------- | ---------------------------------------------------------------------------------- |
| 12   | PULSE_SET     | offset 0 value:u8; offsets 1–7 reserved=0; offset 8 expires_at:i64; total 16 bytes |
| 13   | PULSE_CLEARED | empty, zero bytes                                                                  |

Actor and set_at come from the envelope. No duplicated envelope metadata. Pulse timestamps and as_of are integer UTC Unix milliseconds in [-8,640,000,000,000,000, +8,640,000,000,000,000], the browser Date range (exactly representable integers). SET requires expires_at > envelope timestamp, both in range. Wire duration is any positive interval in range; UI offers only 1, 4 or 8 hours, default 4. Unknown value/nonzero reserved/wrong length/out-of-range timestamp is malformed (2); nonpositive duration is invalid domain (4); unsupported schema/protocol is category 3. CLEAR also validates its envelope timestamp. Existing event timestamp semantics are unchanged.

## Explicit time projection

Rust rebuild_at(events, as_of) validates explicit time and owns expiry: as_of < expires_at is active; as_of >= expires_at is expired. It never reads ambient time. Replay does not filter future-dated events: time is an evaluation input, never log ordering. Clock rollback may make the latest expired Pulse active again. Non-time-sensitive state is unchanged by as_of. Legacy rebuild remains available only for histories without Pulse and rejects Pulse rather than inventing time.

## Protocol v5

All integers little-endian. KINE v5 is exactly a 20-byte header followed by the unchanged 88-byte envelopes and exact payloads:

| Offset | Size | Field       |
| ------ | ---- | ----------- |
| 0      | 4    | KINE        |
| 4      | 2    | version=5   |
| 6      | 2    | reserved=0  |
| 8      | 4    | event_count |
| 12     | 8    | as_of:i64   |

Protocols v1–v4 retain their exact request/result layouts and supported events. They reject both Pulse kinds, including cleared histories. No old reserved bytes are reused. KERR remains v1 with unchanged categories. Browser writer is v5 with an explicit applyEvents(records, asOf) argument; missing/invalid time fails rather than using an implicit clock.

KINS v5 header: offsets 0 magic[4], 4 version:u16=5, 6 reserved:u16=0, 8 item_count:u32, 12 handoff_count:u32, 16 talk_count:u32, 20 pulse_count:u32; total 24 bytes. Follow with existing v2 Item records, v3 Handoff records, v4 Talk records, then Pulse records. Empty result is 24 bytes.

Pulse record: offset 0 actor_id[16], 16 set_at:i64, 24 expires_at:i64, 32 value:u8, 33 status:u8 (0 active, 1 expired), 34 reserved[6]=0; exactly 40 bytes. Old protocols cannot encode nonempty Pulse state. Strict length/reserved/value/status/timestamp checks; no trailing bytes. Limits remain 10,000 events, 10,000 combined entities, and 64 MiB request/result.

## Browser, timers, storage and recovery

kin-pulse owns labeled native value/duration selects and Set pulse, Change and Clear buttons. It renders Rust status; expired/absent displays “No current pulse.” Active shows label and formatted “Until …”. No live countdown. Changes to form selections are transient UI only. KinApp owns commands, busy/focus/feedback and existing failed-command/suspended-refresh recovery.

At submission capture timestamp once; expires_at uses that same snapshot plus duration. Freeze the SET timestamp/value/expiry for original-command retry, including after quota/abort or canonical refresh failure. Retry must not silently extend expiry. Each retry gets an event ID/logical counter through the existing transaction; only committed events count. CLEAR retries are tolerant. New commands supersede older suspended retries. No automatic append on refresh recovery.

IndexedDB stays schema 1 and event-only canonical storage. No mutable Pulse table, migration or source-byte rewrite. Candidate replay with explicit as_of remains inside the atomic event/counter write transaction. BroadcastChannel remains exactly { type: "events-changed" }; receivers reload canonical bytes and replay locally.

Load, canonical refresh, visibility return, window focus and advisory expiry wake-up request Rust replay with a fresh explicit browser time. Timer callbacks never mutate status or append events. Schedule from Rust's active expiry, bound the wake-up interval to at most 60 seconds to recover from clock changes, and recheck even expired state periodically so backward clock changes are observable. Hidden tabs may defer timers; visibility/focus reload canonical storage. Disconnect cancels timers/listeners; reconnect queues refresh without unlocking an in-flight command. Failed refresh uses existing retry, without a tight automatic retry loop. Timer/lifecycle refresh must preserve selections, existing command retry and keyboard focus.
