# v0.14.3 design-development note

## v0.14.4 corrections

- Verified the persistent state notice was detached during lock view rebuilds;
  the same notice node is reattached and browser regression now covers
  unlock → lock → unlock followed by offline and revoked-device states.
- Reconciled desktop navigation with UX-D4 using a centered 600–680px column
  and a compact horizontal destination row, retaining mobile bottom navigation.
- Added a polite route-change announcement and route-specific document title.

## v0.14.5 corrections

- Kept household and security custom elements in block flow so More surfaces
  render as separate, full-width cards.
- Fixed the narrow-screen routine form so its Add button does not create an
  implicit grid column that squeezes the entry field.
- Fixed visual walkthrough captures to visit each destination before saving
  the corresponding desktop and mobile screenshot.

This note compares the shipped v0.14.x experience with the UX contract, four
supplied PNGs, and the supplied interactive prototype. Product and security
truth continues to come from the current implementation.

## Patterns adopted

- A stable five-destination shell: Today, Lists, Routines, Handoff, and More.
  Handoffs and Talk are separate, keyboard-operable views within Handoff.
- A compact Today sequence with catch-up, quick capture, existing actionable
  items, and routine work; owner and classification details remain secondary.
- Warm neutral page/surface colors, a muted green accent, warm attention
  surfaces, quiet borders, restrained shared radii, system typography, and
  operating-system light/dark themes.
- A compact horizontal desktop navigation above a centered reading column,
  responsive mobile bottom navigation, visible keyboard focus, and touch
  targets at or above 44px.
- A forest-green brand header, compact desktop navigation, clearer page
  typography, and a softly highlighted Today introduction make the visual
  system visible at first glance.
- Plain status language tied to actual local, sync, authorization, recovery,
  and deletion state. Offline messaging does not imply remote sync succeeded.

## Patterns intentionally not adopted

- The prototype's preview toolbar, sample-household labels, simulated saved
  state, fabricated data, ornamental plant illustration, and future-concept
  cards are design-preview scaffolding rather than product behavior.
- The desktop home remains a focused single-column surface; it does not copy the
  prototype's secondary dashboard column. Less-frequent trust and continuity
  controls live in More.
- Pulse remains a private, temporary individual signal. There is no comparative
  partner score, passive read receipt, presence, last-active field, or history
  presented as surveillance.

## Capabilities deferred

Shopping and replenishment, new household areas or reference records, household
modes, attachments, maintenance, expanded membership/roles, calendar
interoperability, and routine models or scheduling beyond Kin's existing
daily/weekly recurrence remain outside v0.14.x. No sample data or placeholder
control was added for them.

## Known visual differences

- The real application keeps the brand in a full-width header; the PNGs put
  the brand inside the primary navigation.
- Today uses the product's current item and routine projections. Prototype
  sample chores, handoffs, Pulse text, and household details are not copied.
- The product follows the operating-system theme preference and has no theme
  picker. It omits the preview-mode controls and prototype footer.
- The mobile shell keeps the five current destinations in a fixed bottom bar;
  the content order follows real capability and status rather than preview
  sample cards.

## Accessibility limitations

Browser automation covers keyboard operation, focus, roles/live regions, narrow
reflow, forced colors, reduced motion, text spacing, and page-scale zoom. It
does not certify screen-reader behavior or native desktop zoom. Firefox, Safari,
VoiceOver, and NVDA have not been independently validated for this release.
