# v0.38.2 — Replay & Logical-Time Hardening

## Purpose

Stabilize the existing event history and sync path before v0.39 portability work.
No new household feature or event kind is introduced.

## Behavior

- A cross-device Item completion/reopen or Responsibility change that arrives
  after the target was archived is a deterministic no-op. Same-device commands
  after archive remain invalid, preserving the existing local command boundary.
- Remote events are checked against the already accepted history before they
  are persisted. Malformed canonical bytes and events rejected as semantically
  invalid are quarantined; the relay cursor still advances and later valid
  events can be accepted. The sync status explains that an Adult should review
  the device. Authenticated conflicting bytes for an already known event ID
  remain a hard error.
- Logical time is a positive integer no greater than `9,007,199,254,740,991`.
  A new event can advance the observed maximum by at most `1,000,000`. Rust
  replay, browser encoding/storage, and the relay enforce the same numeric
  bounds with integer-safe arithmetic. This allows the next valid event after
  any accepted event and prevents one extreme event from exhausting the clock.
- Existing valid canonical events and event kinds are unchanged. Replay order
  remains `(logical_time, device_id, event_id)`.

## Limitations

The relay remains opaque and cannot inspect encrypted event semantics. Each
receiving client performs quarantine locally; the encrypted relay record remains
available to other clients until its normal retention or household deletion
path removes it. Real multi-device passkey hardware behavior is a separate
environment-dependent gate.
