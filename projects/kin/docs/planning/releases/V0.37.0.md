# v0.37.0 — Guest & Caregiver Access

**Status:** Implemented candidate on `kin-fast-track-v0.36-v0.38`.

## Shipped behavior

- Adults create a Temporary invitation by choosing a required local date/time. The client sends one finite future timestamp; the pairing service stores `admissionKind: temporary` and `admissionExpiresAt` in trusted server invitation state.
- Temporary invitations use the existing short-lived pairing code, inviter and device binding, claimant passkey, fresh Adult approval, key provisioning, joining passkey activation and single-use confirmation. Client-supplied confirmation kind/expiry is ignored.
- Confirmation persists `kind: temporary` and the invited `expiresAt`. Temporary participants have ordinary Limited participation and no trust authority.
- The server checks expiry on every API request. At or after expiry it marks membership inactive, revokes devices and sessions, and sets the existing rotation-pending state. Future events/keys are withheld until an Adult rotates the key epoch. No scheduler is required.
- Adults can revoke Temporary access before expiry through the existing fresh-passkey member-removal flow. Expiry reconciliation is repeat-safe; manual revocation uses the existing one-way removal transaction.
- Responsibility selectors exclude revoked and expired devices; settings show Temporary access end time and use a target-specific revoke action. Expired access remains marked ended after durable identity backup/reload.
- Kin cannot remotely erase plaintext already decrypted by an offline device. A device reconnecting at/after expiry cannot sync or obtain future key epochs/events.
- Server identity backup preserves kind and absolute expiry. Kin's local content archive continues to contain event history/context, not server trust authority.
