# v0.39.0 — Portable Household Export v2

**Target date:** 2026-10-30

**Status:** Implementation candidate; final release gate and human review are pending.

## Goal

Add an explicit package-v2 manifest to the existing encrypted household archive
without changing the KARC v1 frame or the canonical event encoding.

## Product rule

Deliver one understandable household capability without making Kin feel like enterprise project management.

## Architecture constraints

- Preserve canonical event history and deterministic Rust/WASM behavior where the capability enters household state.
- Preserve local-first and encrypted-sync boundaries.
- Keep plaintext household semantics client-side.
- Define persistent-format migration before changing storage.
- Prefer native Web APIs and existing Kin abstractions.
- Do not add AI, scoring, surveillance, or hidden inference.

## Implemented package

- Outer `archiveVersion: 2` identifies the package contract. KARC framing stays
  version 1, so existing container readers and size checks remain in use.
- The authenticated manifest contains `packageFormatVersion`, Kin version,
  export time, canonical event count, attachment count, ciphertext byte count,
  and integrity metadata version. Counts and bytes are checked against the
  decrypted payload before restore is permitted.
- The encrypted body contains the existing format-2 snapshot: byte-identical
  canonical events, protected local context, and attachment records. It does not
  contain search indexes or projected/derived domain caches.
- AES-GCM authenticates the package metadata and full payload. Each protected
  attachment retains its stable ID, encrypted bytes or local protected payload,
  digest and event-bound parent association. Restore verifies attachment
  digests and parent bindings; no corrupt attachment is skipped.
- The existing 10,000-event, 64-attachment, 50 MiB aggregate attachment
  ciphertext, 1 MiB metadata and 160 MiB complete archive bounds remain in
  force.
- The importer continues to accept documented package-v1 archives. Unknown
  future versions, malformed manifests, unsupported snapshot formats, invalid
  canonical replay, duplicate event IDs and corrupt attachments fail closed.

## Authority boundary

When an authenticated sync connection is available, the encrypted package also
preserves a bounded membership snapshot: stable member IDs, explicit Adult,
Limited or Temporary kind, active/removed/expired status and absolute Temporary
expiry. Expired Temporary records remain expired. Unknown explicit kinds and
invalid expiries fail closed. These records are descriptive household data;
they never create membership, credentials, device trust, sessions or server
authorization. Legacy archives without this snapshot remain supported under
their existing compatibility rules.

Export preserves locally available history and attachments. For a synced
household it refreshes membership from the authorized device directory; if the
directory is unavailable and no previous membership snapshot exists, export
fails rather than omitting membership. An attachment whose protected payload
is not present locally also makes export fail. An archive can be opened only
with its recovery key. Restore requires an empty target and never creates an
Adult, approves a device or grants sync access. After restore, the owner can
complete ordinary household approval on the device and let authorized sync
reconcile newer state.

## Release gate

The package and restore regression results are recorded in the milestone
commit and final batch report. Real-household migration and hardware passkey
approval remain environment-dependent. Do not describe the candidate as
production certified.
