# v0.38.4 — PWA & Archive Preflight

## Purpose

Make installed clients stage the current shell safely and align bounded archive
capacity with Kin's documented attachment contract before v0.39.

## Behavior

- The document release version is passed to the service worker, which derives
  a release-specific cache. A complete shell must stage before activation;
  failed staging is deleted while the previous cache remains available.
- Archive and protected snapshot bounds are 160 MiB. Attachment ciphertext is
  capped at 4 MiB plus 4096 bytes per item, 64 attachments per household, and
  50 MiB aggregate. Browser storage, relay, archive codec, and export use these
  explicit bounds.
- No decrypted household data is added to the static shell cache.

## Regression evidence

- Service-worker tests cover versioned staging, old-cache cleanup, failed
  staging retention, and offline navigation.
- Original B-007 code-path finding is addressed by release-derived cache names;
  `scripts/check_version.py` verifies release metadata and registration.
- Original B-008 reproduction passes for 0, 1, 11, 12 and 13 attachments,
  including exactly 50 MiB aggregate. Browser and relay aggregate-boundary
  tests pass. Rust archive bounds are covered by archive tests.
- Real installed-browser update path: UNVERIFIED — ENVIRONMENT.

## Limitations

The 160 MiB archive bound is finite. An export above the documented bound is
rejected with a clear message.
