# v0.26.0 — Pins & Quick Access

**Status:** Feature-branch implementation candidate; not tagged or published.

## Shipped capability

- Add explicit Pin and Unpin canonical events for stable existing Item, Note,
  Routine, and Area IDs. The UI currently offers Item Pins, including Staples.
- Bound the household to 10 pins. Duplicate pin delivery is idempotent;
  unpinning an absent target is a safe no-op.
- Preserve insertion order under deterministic distributed replay. Manual
  reordering is intentionally deferred.
- Add compact Quick Access to Today, with keyboard accessible Open and Unpin
  actions. Archived targets are removed from the projection.
- Keep Pins in canonical local event history, which follows the existing local
  encryption and encrypted sync path. No server plaintext target index is added.

## Compatibility

Protocol 18 adds event kinds 31 (`PIN_ADDED`) and 32 (`PIN_REMOVED`) with a
target type and stable 16-byte ID. Protocol 18 adds a bounded Pin list to the
state projection. Histories from protocols 1–17 still replay with an empty Pin
list. Older projections reject states containing Pins instead of dropping them.
No IndexedDB, archive, or server schema migration is required.
