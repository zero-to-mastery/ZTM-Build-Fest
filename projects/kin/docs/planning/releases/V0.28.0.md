# v0.28.0 — Local Reminders

**Status:** Feature-branch implementation candidate; not tagged or published.

## Capability

- An explicit Item or Routine reminder action can request the native Notification permission and schedule one foreground page timer for a future local date/time. Permission is never requested during startup.
- Denied and unsupported notifications return clear status while leaving Kin usable. An Item reminder is canceled when its planning date changes, it is completed, or it is archived; delivery also checks that the Item remains active. A same-ID reminder replaces an earlier timer.
- No server, push provider, external dependency, engagement loop, or canonical event was added. Reminder state lives only in page memory and does not synchronize or survive a reload.

## Platform limits

A JavaScript timer cannot guarantee delivery after the browser is terminated, the operating system suspends background activity, the page is discarded, or service-worker support is unavailable. Notifications may be delayed or suppressed. Kin does not promise native scheduled-notification behavior.

## Validation

`web/reminders.test.mjs` covers permission outcomes, duplicate replacement, cancellation, completed-Item suppression, and local date boundaries. Browser delivery and permission UI require real-browser execution.
