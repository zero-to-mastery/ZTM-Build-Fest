# v0.21.0 — Household Modes

**Target date:** 2026-10-12

**Status:** Implementation and validation complete on
`kin-fast-track-v0.21-v0.25`; unpublished candidate, not production
certification. No tag is created on the batch branch.

## Capability contract

- Add the fixed household modes Normal, Vacation, Guests, and Rest, with
  Normal as the default for histories that contain no mode event.
- A non-Normal mode pauses routine occurrences without changing routine
  definitions. Rust rejects occurrence completion/reopen commands while
  paused; archiving a routine remains available.
- Persist explicit member mode changes as canonical schema-1
  `HOUSEHOLD_MODE_CHANGED` event kind 29, carrying one mode byte. Distributed
  replay uses the existing `(logical_time, device_id, event_id)` ordering, so
  concurrent offline changes converge deterministically.
- Add replay protocol 15. Protocols 1–14 reject mode events or non-Normal
  mode projections instead of omitting the new state. Protocol 15 appends a
  four-byte mode/reserved field to the result header; prior layouts remain
  unchanged.
- Keep mode events in the existing local encrypted event store, encrypted
  sync envelope, and KARC history. No IndexedDB, server, archive, or sync
  envelope migration is required; no plaintext household state is added to
  the server.
- Expose a native keyboard-operable selector on More. Paused routines remain
  visible, with occurrence actions hidden and an explanation; routine
  definitions can still be archived.
- Keep the mode enum closed and bounded; do not add automatic schedules,
  location inference, reminders, assignments, or background mode changes.

## Compatibility and limits

Mode events use the existing 10,000-event and 64 MiB protocol bounds. Old
histories project to Normal without rewriting source bytes. Identical event
redelivery remains idempotent; distinct concurrent mode changes use the
existing deterministic distributed replay order. Older protocol clients fail
closed on data they cannot represent. Revocation continues to govern access
to the complete encrypted event stream.
