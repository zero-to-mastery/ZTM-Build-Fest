# v0.31.0 — Maintenance Records

**Target date:** 2026-10-22

**Status:** Implemented candidate; local validation only, not production certification.

## Goal

Track simple maintenance facts and next actions around household reference records.

## Product rule

Deliver one understandable household capability without making Kin feel like enterprise project management.

## Architecture constraints

- Preserve canonical event history and deterministic Rust/WASM behavior where the capability enters household state.
- Preserve local-first and encrypted-sync boundaries.
- Keep plaintext household semantics client-side.
- Define persistent-format migration before changing storage.
- Prefer native Web APIs and existing Kin abstractions.
- Do not add AI, scoring, surveillance, or hidden inference.

## Required implementation questions

- What new domain state or event is actually necessary?
- Can existing events/state represent the feature more simply?
- What happens offline?
- What happens across two devices?
- What happens after retry/restart?
- What does export/import do with it?
- Does member/device revocation affect it?
- What are the size/count limits?
- What is the migration from the prior supported version?
- What must be accessible by keyboard/screen reader?

## Implemented capability

- Protocol 21 adds schema-1 `MAINTENANCE_EVENT_SAVED` and `MAINTENANCE_EVENT_ARCHIVED` facts. Saving an existing event ID records a correction; event bytes remain immutable.
- Events are scoped to an active Reference Record and may link to an active Routine. Performed date is required, next date is optional and cannot precede it.
- Maintenance history is kept in the household event stream, so existing local encryption, offline replay, encrypted sync and event export/import apply without a separate persistence system.
- Per Reference Record lifetime limit: 64 entries. Summary text is trimmed plain text up to 240 UTF-8 bytes. The protocol projection caps total rows at 8,192.
- History is ordered by date descending in the UI with a stable ID tie-break; the reducer's canonical event order remains the replay authority.
- Archiving a Reference Record preserves its maintenance history. New edits/events against the archived record fail closed.

## Verification

Native Rust and real WASM tests cover create/edit/archive, concurrent offline events, linked and invalid Routine references, bounds, old histories, and projection decoding. The full Node suite passes. Existing canonical events reuse current local encryption, sync, and archive/import paths; no attachment/blob transfer applies to this release.

Manual browser keyboard/screen-reader, 320px, 200% zoom, mobile, forced-colors, and live encrypted two-device sync checks remain unverified in this environment.

## Release gate

- Migration behavior is tested where needed.
