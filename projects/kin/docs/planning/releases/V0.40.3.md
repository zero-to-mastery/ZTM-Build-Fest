# v0.40.3 — CI & Verification Infrastructure

**Candidate:** `kin-v0.40.3` on `chore/kin-v0.40.3-ci-verification`, based on `kin-development` after PRs #37 and #38. This patch adds local verification infrastructure and a proposed workflow handoff. It does not add product behavior or change persistent contracts.

## Verification entry points

- `npm run verify` checks Node/Rust/Python/Git prerequisites, Rust formatting, warnings-denied Clippy, version consistency, all discovered server and web Node tests, Rust tests, the release WASM build, and byte-for-byte parity if the repository tracks the generated WASM artifact.
- `npm run verify:browser` runs the existing browser, storage, UI, passkey, and household authority regressions. Set `KIN_BROWSER` to a Chromium-family executable or pass its path after `--browser`.
- `node --test scripts/verify.test.mjs` checks fail-fast stage reporting, prerequisite handling, discovery, path resolution, child exit/start errors, SIGINT/SIGTERM cleanup, cleanup races/errors, listener removal, and explicit optional-stage reporting.

Mandatory commands fail fast. The first failed command is reported as `FAIL`; checks skipped within or after that stage are reported as `NOT RUN` with the skip reason. The overall exit code is nonzero, and completed results are retained. The default mode reports browser suites as `NOT RUN`; browser mode stops at its first failing required suite.

The runner handles SIGINT and SIGTERM while a child is active. POSIX children use an isolated process group, and cleanup signals that group. Windows cleanup uses built-in `taskkill /T /F` scoped to the child PID. The runner waits for cleanup, removes signal listeners, and treats cleanup errors as failures. This does not guarantee cleanup of descendants that deliberately detach from the group/tree or survive host-level process failures.

The process-tree regression was executed on Windows and verified the isolated descendant was gone after cleanup. POSIX process-group cleanup is implemented but was not exercised in this Windows environment.

The browser suites use isolated temporary profiles and synthetic data. They do not represent human fingerprint comparison or physical-device validation. Browser runs require a CDP-capable Chromium-family browser. The present storage/UI scripts also use PowerShell for process cleanup on Windows, so Linux/macOS support for those existing suites is not claimed.

## Existing security and recovery coverage

The existing full suites remain in the gate. The household authority browser drill covers member admission, Limited/Temporary authorization, device/member revocation, Temporary expiry, the committed-rotation recovery race, portable archive validation/export/restore without device authorization, browser clock skew versus the injected service clock, and two-client reconciliation. `server/rotation-recovery.test.mjs` and `server/durable-sync-integrity.test.mjs` preserve B-002 recovery, historical signing-key verification, and encrypted history across restart/revocation cases. No security/recovery tests were rewritten or disabled.

## CI integration

No active GitHub Actions workflow is configured. Kin's `AGENTS.md` prohibits parent repository changes, including root-level workflows. A minimal proposed workflow is stored at `docs/ci/kin-verification.workflow.yml`; it is not discovered or executed from that location. Root-level placement requires separate repository-scope authorization.
