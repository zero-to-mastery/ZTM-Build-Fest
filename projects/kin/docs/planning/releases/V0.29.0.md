# v0.29.0 — PWA & Offline Install Polish

**Status:** Feature-branch implementation candidate; not tagged or published.

## Manifest

The local manifest declares name, short name, description, root start URL and scope, standalone display, theme/background colors, and a repository-local SVG icon. Shortcuts and categories are optional metadata.

## Install and update experience

An `Install Kin` button appears under More only when the browser provides its native `beforeinstallprompt` event. Kin does not prompt automatically. A ready update is offered without forced activation; choosing it is blocked while an Item, Routine, Playbook, or Note draft is being edited.

## Service worker

- Install fetches every listed static shell asset into a new versioned cache and rejects installation if any response fails, is opaque, or is unsuccessful. The prior active worker and cache remain available when staging fails. Activation occurs only after the user chooses an update (or during first install), claims clients, then removes obsolete `kin-static-*` caches.
- Navigation to `/` and `/pair` falls back to the cached index without caching the requested URL. The allowlisted app modules, CSS, WASM, manifest and local assets are cache-first. API routes and household data, keys, drafts, archives and decrypted projections are excluded.
- An update-ready message offers `A new Kin version is ready.` and `Update now` / `Later`. Reload occurs only after the explicit update action and controller change.

## Limits and validation

Cache Storage does not verify the integrity of already cached asset bodies beyond the browser-reported response status and fetch/cache operations. No checksum system is added. PWA install, update rollout and offline launch still need real-browser confirmation; the repository includes Node tests for manifest metadata, complete-shell staging, failed staging retention, and activation cleanup.
