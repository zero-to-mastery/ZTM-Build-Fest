# v0.34.0 — Responsibility Ownership

**Status:** Implementation candidate in PR #30.

Items and Routines can be unassigned or explicitly assigned to one existing household member ID. A member can take responsibility, hand an entity to the other active household member, or clear it. The UI does not assign a partner silently and displays only “You” or “Household member.”

Protocol 23 adds the canonical `RESPONSIBILITY_CHANGED` event and a bounded projection table. Replay sorts by the existing `(logical time, device ID, event ID)` order, so concurrent assignments converge on the last event in that order. A later clear also wins by that order. Commands reject unknown or archived targets and no-op assignments. Duplicate delivery remains idempotent through existing event identity checks.

When sync discovers that an owner has no active, unrevoked device in the authorized directory, the client appends a canonical clear event. Historical events remain in the household log; current projection becomes unassigned after that clear is reconciled. This requires sync to observe the membership change. Offline devices converge on reconnect.

Responsibility is not added to Notes, Reference Records, Maintenance Records, or attachments. There are no contribution scores or workload analytics.
