# v0.35.1 - Fresh Passkey Self-Removal

**Status:** Corrective implementation candidate on `kin-v0.35-more-adults`;
security re-review required. No tag, merge, or v0.36.x work is authorized.

Self-removal now requires fresh passkey authentication before membership/device revocation and access-change rotation.

## Security contract

- Keep the destructive confirmation, then request a fresh WebAuthn assertion
  through the existing membership removal options/finish endpoints, targeting
  the authenticated adult's own member ID.
- The single-use, two-minute server challenge binds the removal purpose,
  target member, acting member, and acting device. The existing verifier checks
  the assertion against that member's credential and requires user verification.
  No second authentication system or reusable fresh-auth token is introduced.
- The old session-only membership DELETE endpoint returns `fresh_auth_required`.
  An unverified, cancelled, expired, wrong-purpose, wrong-device, or wrong-member
  ceremony cannot mutate membership.
- Only after assertion verification, use the existing durable transaction to
  deactivate membership, revoke every departing device, invalidate every
  departing session, revoke pending/claimed invitations authored by that adult,
  and perform the existing access-change hook.
- Access change preserves the current epoch and marks the next epoch pending;
  it removes provisioning grants involving excluded devices. It does not
  invent synchronous client key generation. Existing rotation blocks writes
  until the remaining authorized devices complete provisioning.
- On persistence failure the durable transaction rolls back and storage fails
  closed; restart restores committed authority. No success response or local
  lock is issued for failure. Existing volatile sessions/ceremonies do not
  survive restart.
- Preserve last-active-adult protection and existing member/device authorization,
  pairing, recovery, legacy two-adult membership/history, and four-adult limits.
- Clear session and trusted-device cookies on successful self-leave, then lock
  local authority and navigate to the locked shell. Passkey cancellation/failure
  has accessible feedback and does not sign out or partially leave.

## Validation

Targeted HTTP regressions cover session-only rejection, fresh proof, replay,
expiry, wrong member/device/purpose, two/four-adult households, last-adult
protection, multiple devices/sessions, invitation revocation, sync denial,
pending epoch persistence, and injected access-change persistence failure.
Component regressions cover confirmation, cancellation, accessible status/error
feedback, rejected mutation, and the shared assertion helper. The virtual
authenticator runner exercises real invalid UV/signatures and successful
component self-leave against the production verifier.

This patch does not
rewrite the [v0.35.0 milestone](V0.35.0.md) or claim an independent audit,
physical-authenticator, screen-reader, Safari, or Firefox certification.
