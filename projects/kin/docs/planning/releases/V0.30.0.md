## Implementation contract

Reference Records are canonical encrypted household records with a title, optional Area, and one to sixteen labeled text fields. A record is edited as one bounded save event and archived with a terminal archive event. Limits are 128 records, 128 UTF-8 bytes per title, 64 bytes per label, and 1,024 bytes per value. No server plaintext index, reminders, or field-specific semantics are introduced.

Protocol 20 adds event kinds 35 and 36 and appends the bounded records after Playbooks. Older protocols retain their prior layouts and reject histories containing these events or records. Existing IndexedDB and encrypted sync containers store opaque canonical event bytes, so no storage or server migration is needed. The current application can only replay protocol 20 histories; households should update active devices before creating reference records. Concurrent edits resolve by the existing deterministic replay order. An archive remains terminal when a same-logical-time save arrives from another device.

Reference text is rendered as text, kept within the existing client-side encrypted event boundary, and included in local household exports through event history. It is not included in the current general search index. The editor is keyboard-operable and labels every control; screen-reader and cross-device behavior still require release-gate verification.
