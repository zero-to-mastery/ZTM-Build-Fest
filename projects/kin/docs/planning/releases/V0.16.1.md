# v0.16.1 — Notes Correctness

This completed correctness gate is followed by the separate
[v0.16.2 resilience and accessibility gate](V0.16.2.md). This historical record
and its release semantics remain unchanged.

**Status:** User review follow-up on PR #26; implementation in progress on `kin-v0.16.x-notes`.

## Scope

Correctness fixes for the v0.16.0 Notes capability. This patch does not add a
new product capability, event kind, protocol version, or persistent schema.

## Required outcomes

- For equal-logical-time `NOTE_UPDATED` and `NOTE_ARCHIVED` events from
  different devices, terminal archive wins regardless of device-ID ordering.
  The concurrent update is ignored; ordinary non-concurrent update-after-
  archive remains invalid.
- Browser title/body validation mirrors Rust's trim, Unicode scalar, UTF-8 byte,
  and control-character constraints. Validation errors are associated with the
  affected field, and invalid submissions append no Note event.
- Keyboard browser regressions wait for the requested persisted state rather
  than treating an idle state observed before event handling as completion.
- The service worker cache version changes and includes the Notes component.

## Validation

Run the full Rust, Node/real-WASM, browser, sync/security/storage, formatting,
Clippy, release WASM, version consistency, and diff checks. Repeat the browser
regression to show that the keyboard Handoff/Talk assertions are stable.

## Compatibility

Protocol 10, canonical event bytes, IndexedDB, KARC, sync envelope, and server
metadata remain unchanged. The `kin-v0.16.0` annotated tag remains immutable.
