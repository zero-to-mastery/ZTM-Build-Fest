# v0.38.3 — Trust & Access Hardening

## Purpose

Close the audited household trust-boundary gaps before portability work.

## Behavior

- Only active Adults can enable household sync. Limited and Temporary members
  can participate after an Adult enables it.
- Destructive device revocation requires a fresh passkey ceremony bound to the
  selected target device and Adult member. The legacy session-only DELETE is
  rejected. Revocation and sync access changes use the existing transactional
  access-change path.
- Last-Adult checks count only another active Adult with a registered
  credential and at least one unrevoked trusted device. Removing the final
  usable Adult is rejected.

## Regression evidence

- Pairing, HTTP authorization, sync service, and household UI tests pass.
- Original B-004 and B-006 reproductions pass: session-only revocation is
  rejected; self-leave is blocked when it would leave no usable Adult; Limited
  and Temporary sync enable is rejected while Adult enable and authorized
  participation succeed.
- B-005's original session-only revocation path is rejected with
  `fresh_auth_required`; target-bound passkey success and wrong-member proof
  are covered by `server/sync-http.test.mjs`.

## Limitations

Already decrypted copies on a revoked device cannot be erased remotely.
