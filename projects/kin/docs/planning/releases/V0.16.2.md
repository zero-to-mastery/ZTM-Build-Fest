# v0.16.2 — Notes Resilience & Accessibility

**Status:** Validated implementation candidate on `kin-v0.16.x-notes`, PR #26. This is a
resilience/accessibility patch to the existing Notes capability; it adds no
Note operation, event kind, or household-data field.

## Changes

- Keep Note editor contents in component memory across ordinary rerenders and
  focus changes. Clear that editor after a successful persisted operation. The
  protected Notes component and its in-memory draft are removed on lock; drafts
  are not put into IndexedDB, household events, or sync.
- Give title, body, and Area controls explicit labels and unique IDs. Associate
  each field with its own help and validation message. Clear stale validation
  state on a valid submission and restore focus according to the completed
  action after the app's busy-state and canonical-state rerenders.
- Report the saved-local state separately from sync availability. Canonical
  EventStore append and Rust replay remain authoritative: a stale edit is
  evaluated against the current stored event history, and an archived Note
  cannot be revived by an old tab.
- Keep Note content in protocol-10 canonical events. The existing encrypted
  relay carries ciphertext and routing metadata; no plaintext Note index or
  server-side Note authorization was added.

## Offline, retry, and multi-device behavior

Notes use the existing local event transaction/outbox and encrypted sync
coordinator. Offline create, update, and archive therefore persist locally and
are eligible for normal later sync. Duplicate canonical event delivery remains
deduplicated by existing event identity and replay behavior. Concurrent updates
use the established distributed event ordering; equal-logical-time cross-device
update/archive still resolves to terminal archive as specified by v0.16.1.

The browser gate exercises persisted lifecycle reload, offline event creation
and recovery, stale state, cross-device delivery, duplicate delivery, and
failure paths. Exact execution counts and remaining gaps are recorded after
validation.

## Lock, Areas, and archive compatibility

Lock removes the protected application view and Notes component; unsaved Note
drafts are discarded. Unlock reconstructs Notes from protected canonical
events. Notes continue to refer to Areas by stable `areaId`, so renamed Areas
project their current name while archived Area history remains marked. Stale
assignment to an archived Area is rejected by Rust validation.

No server schema, sync envelope, IndexedDB schema, or KARC framing change is
introduced. Generic encrypted archive/export continues to carry canonical Note
history and remains local-history-only; archive import does not restore server
authority.

## Accessibility and limits

The Notes structure uses a section heading, list/list-item semantics, explicit
field labels, field-specific descriptions, native buttons/controls, textual
Area context, and status/error feedback through existing application live
regions. Validation marks only the affected field. Focus is restored after
create, edit, archive, and state rerender. The structural audit does not claim
screen-reader certification; no direct NVDA or VoiceOver testing is claimed.

The v0.16.0 contract remains intact: `NOTE_CREATED`, `NOTE_UPDATED`, and
terminal `NOTE_ARCHIVED`; protocol 10; 128 lifetime Notes; 80 Unicode-scalar /
256 UTF-8-byte title bounds; 4096 UTF-8-byte body bound; optional stable
`areaId`; plain-text rendering; no plaintext server semantics. The
`kin-v0.16.0` and `kin-v0.16.1` annotated tags are immutable.

## Validation and remaining limitations

Validation completed: 133 Rust tests passed; Clippy with warnings denied,
format check, and `wasm32-unknown-unknown` release build passed. The Node suite
passed 307 tests with no failures or skips. The full Edge browser regression
suite passed three consecutive runs on Edge 154 / Windows x64, including Notes
offline lifecycle, stale-write rejection, archived reload, accessibility
structure, encrypted sync/storage, and existing household regressions. The
version consistency check and `git diff --check` passed. Cross-browser rendering,
physical multi-device operation, native desktop zoom, and assistive-technology
certification remain outside the claims unless those environments are exercised
directly.
