## Goal

Make accumulated household context findable locally and privately.

## Prerequisite

The previous release line has passed its gate.

## Product rule

Deliver one understandable household capability without making Kin feel like enterprise project management.

## Architecture constraints

- Preserve canonical event history and deterministic Rust/WASM behavior where the capability enters household state.
- Preserve local-first and encrypted-sync boundaries.
- Keep plaintext household semantics client-side.
- Define persistent-format migration before changing storage.
- Prefer native Web APIs and existing Kin abstractions.
- Do not add AI, scoring, surveillance, or hidden inference.

## v0.25.0 implementation outcome

- Search is a local, in-memory projection over existing decrypted state:
  unarchived Items and their unarchived checklist Steps, non-archived
  Handoffs/Talks, and unarchived Notes. Completed Items, acknowledged Handoffs,
  and resolved Talks remain findable.
- Matching is trimmed, case-insensitive substring search. It adds no query
  language, ranking, actor attribution, telemetry, event, protocol field,
  persistent index, storage migration, or server behavior.
- Classification, status, and Area filters apply to Item and Step matches
  only; matching Handoffs, Talks, and Notes remain visible.
- Searches work offline against the current unlocked projection. Existing
  encrypted sync and archive flows already carry the source records, so no
  search state is transferred. Queries and filters are cleared with the
  component tree on lock and are not saved across restart.
- The search scans the bounded replay projection and renders at most 100
  matches while announcing the total count. New content needs no migration;
  older supported event histories are searched as replayed.
- Native form controls, visible labels, a polite status announcement,
  keyboard focus retention, and a focused Edge regression cover accessibility.
