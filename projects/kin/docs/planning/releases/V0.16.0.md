## Goal

Add durable short-form reference context that helps people act without turning Kin into chat or a document editor.

## Prerequisite

The previous release line has passed its gate.

## Product rule

## Architecture constraints

- Preserve canonical event history and deterministic Rust/WASM behavior where the capability enters household state.
- Preserve local-first and encrypted-sync boundaries.
- Keep plaintext household semantics client-side.
- Define persistent-format migration before changing storage.
- Prefer native Web APIs and existing Kin abstractions.
- Do not add AI, scoring, surveillance, or hidden inference.

## Implemented capability record

Notes use stable 128-bit IDs and schema-1 events 22–24 under additive replay
protocol 10: `NOTE_CREATED`, `NOTE_UPDATED`, and terminal `NOTE_ARCHIVED`.
Protocol 1–9 request/result layouts remain unchanged and fail closed on Note
events. Rust validates title/body, Area references, lifecycle, count, canonical
encoding, and projection. The maximums are 128 lifetime Notes, 80 Unicode
scalars/256 UTF-8 bytes per trimmed title, and 4096 UTF-8 bytes per body. The
maximum encoded event is roughly 4.5 KiB before sync wrapping, within the
existing 8 KiB encrypted envelope. Plain text supports tab and line breaks;
other controls are rejected. Archive is terminal.

Notes live under More. The browser uses native labelled form controls, an
optional existing active Area selector, safe text rendering, and create/view/
edit/archive operations. Existing associations remain visible through Area
rename/archive; replay preserves stale pre-archive events. Note text remains in
the existing encrypted event payload. No server interpretation, IndexedDB
schema, KARC framing, or sync envelope change is made. Existing histories replay
to `notes = []` without synthetic events.
