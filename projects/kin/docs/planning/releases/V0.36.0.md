# v0.36.0 — Limited Household Members

**Status:** Implemented candidate on `kin-fast-track-v0.36-v0.38`.

## Shipped behavior

- An active Adult can choose Add Adult or Add Limited Member. Both use the existing short-lived pairing code, inviter/device binding, claimant passkey, fresh Adult approval, joining passkey activation, one-use confirmation, and existing key provisioning.
- The selected kind lives in server-held invitation state. Confirmation ignores client-supplied kind and expiry fields.
- Active membership is bounded to 12 participants, with at most four Adults and eight Limited Members. Temporary Members share the 12-person household bound.
- Limited Members can sync ordinary household events and participate in Responsibility. Pairing creation, invitation lookup/revocation, device listing/approval/revocation, member removal, recovery approval, household deletion, and key administration require Adult authority server-side.
- Server schema v5 persists `kind` and optional `expires_at`. Older database rows migrate as Adults. Temporary kinds require an expiry and remain expired after durable backup restore.
- Kin's user-export archive contains household event history and local context, not trusted server membership. Durable server identity backup/restore carries the canonical kind and expiry.
- Temporary invitation creation is implemented in the server flow as preparation for v0.37; the Adult-facing expiry UI and full expiry release gate belong to v0.37.
