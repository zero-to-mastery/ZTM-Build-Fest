# v0.40.0 — Restore & Device Migration UX

**Target date:** 2026-10-31

**Status:** Implementation candidate; final release gate and human review are pending.

## Delivered behavior

- More → household data provides a keyboard-operable `.kin` file picker and recovery-key field.
- Kin checks size, format compatibility, recovery authentication, canonical replay, membership representation, attachment integrity and parent binding before changing active storage.
- A validated event/attachment summary is shown with a separate Restore household confirmation. Focus moves to the confirmation; validation and outcome messages use the existing live status region.
- Staged plaintext exists only in memory. Cancel, lock or reload discards it. Final promotion is one IndexedDB read/write transaction that verifies the target remains empty; interrupted writes abort atomically.
- A same-household archive can be accepted as an idempotent no-op when every archived event and attachment is already present with matching content. Other non-empty targets are preserved and restore is refused.
- Restored data does not include passkeys, sessions, device keys, household key epochs or server authorization. A device must complete the existing pairing/approval and key provisioning flow before sync starts.
- Once the device is normally approved, the existing encrypted sync path binds imported history to that approved identity, deduplicates matching canonical event IDs and applies current authorized state. Conflicting bytes for one event ID fail closed. Current membership, revocation and key access remain server-authoritative.
- Temporary expiry remains an absolute timestamp. Expired Temporary entries stay expired, and removed-member entries remain informational data; neither creates authority.
- Offline restore is local. Sync can begin after the service returns and normal device approval succeeds.

## Format and resource limits

v0.40 uses package format 2 in KARC v1 framing and retains package-v1 import compatibility. Parsing is bounded to 160 MiB, 10,000 events, 64 attachments and 50 MiB attachment ciphertext. Search indexes and derived caches are rebuilt.

## Collision and interruption behavior

An empty local installation may restore a validated package. On a non-empty installation, a same-household archive is accepted as an idempotent no-op only when every archived event and attachment is already present with matching content; this permits re-opening an export or importing a stale subset without resurrecting anything. Different-household archives and same-household archives containing missing rows are refused before active storage changes. The implementation does not merge missing archive rows into a populated store. For migration catch-up, restore to a fresh local installation and complete ordinary device approval and sync.

Staging is an in-memory validated snapshot rather than a durable staging database. Reload safely discards it. Promotion is atomic at the IndexedDB transaction boundary. The browser regression covers corruption, lock interruption, retry, same-household idempotence and non-empty-target refusal; a full browser-profile migration with real household approval requires an available service and passkey environment.

## Accessibility and limits

The restore controls use labels, keyboard submission, focus placement, and the existing `role=status`/`role=alert` regions. Detailed assistive-technology certification, real mobile browsers and real-hardware passkeys remain environment-dependent. Restore does not recover a lost passkey or authorize an Adult by itself.

### UNVERIFIED — ENVIRONMENT

- A real household migration using a separate browser profile, live household approval, and physical passkeys was unavailable. The automated browser regression uses isolated fixtures and does not count as that drill.
- Screen-reader certification and real mobile browser/PWA migration were not run.
- Same-household restore into an already populated local store succeeds only when all archive events and attachments are exact members of current household data. Importing missing historical rows into a populated store remains unsupported; use a fresh local installation and normal sync catch-up.
- Restore staging is memory-only and is safely discarded by reload or lock. The browser exercises validation failures, cancellation, lock interruption and transactional promotion failure; process termination during native IndexedDB promotion is not directly injectable in this environment.

This candidate is not production certification. No v0.41 feature work is included.
