# v0.15.x — Household Areas

**Current gate:** v0.15.5 — Area form accessibility and release-state reconciliation.
The preceding v0.15.0–v0.15.4 milestones are complete. Do not begin v0.16.x
without explicit authorization.

Areas answer: **Where or what part of household life does this belong?** They
are optional place/context for household content. They are not projects,
folders, workspaces, permission boundaries, teams, or productivity categories.
The core rule remains capture first, organize later.

## Domain contract

```text
Area { id: stable AreaId, name: user display value, archived: bool }
Item.area_id: optional AreaId
```

Areas are flat. Only Items receive assignments in this line. “No area” is a
valid state and clearing an assignment never deletes or changes the Item.

- IDs are stable 128-bit opaque values; the all-zero value is reserved for no
  Area in the assignment event and cannot identify an Area.
- Names are trimmed at Unicode whitespace, preserve remaining user spelling,
  and reject empty values, controls, more than 48 Unicode scalar values, or
  more than 96 UTF-8 bytes. NFC canonicalization is not performed.
- Current commands reject names that compare equal after Unicode lowercase
  conversion and trimming, including names held by archived Areas. Concurrent
  offline creates/renames are never merged during replay; both stable IDs
  survive. The UI distinguishes duplicate labels with a short ID suffix.
- The lifetime Area count is capped at 32, including archived Areas. There is no
  hard delete, nested hierarchy, or automatic Area creation.
- Archive retains existing assignments. Once a device knows an Area is
  archived, Rust rejects new assignments to it. A stale offline assignment
  authored before the archive is still replayable and remains historical
  context after deterministic sync convergence.

## Canonical events and persistence

Protocol 9 adds schema-1 event kinds 18–21: `AREA_CREATED`, `AREA_RENAMED`,
`AREA_ARCHIVED`, and `ITEM_AREA_CHANGED`. Rust validates commands, reduces
events, enforces count/name bounds, and encodes/decodes Area projection state.
JavaScript owns the DOM, event-store transaction, Web Crypto, IndexedDB,
network, and focus. No parallel UI-only Area model exists.

There is no IndexedDB, server database, or KARC archive-format migration.
Existing event bytes are immutable. Pre-Area histories replay without
synthetic Areas. KARC v1 export/import carries Area events inside the existing
encrypted canonical event body. Sync envelopes and their server metadata
contract are unchanged: plaintext Area names remain inside encrypted event
payloads. Revocation, backups, and restore follow the existing whole-household
event/key boundaries. Older clients fail closed on unknown Area kinds; they may
not skip or rewrite them.

## UI placement

Areas live at **More → Areas**, not in primary navigation. The manager makes
create, rename, and archive direct and lightweight. Item selectors are
secondary to Item text, retain “No area,” expose archived historical context,
and never enter quick capture. Filtering is omitted from the foundation unless
a later line can add it without a new navigation destination or query builder.

remains valid for households with no Areas, while projection refuses to drop
Area state on protocols before v9. Existing rules preserve assigned IDs through
rename/archive, replay stale pre-archive assignment as historical context,
reject a new assignment to an archived or missing Area, and never synthesize an
Area for old event histories. Duplicate known-name commands are rejected;
independently created IDs from concurrent devices remain distinct during replay.
KARC v1 has no shape change: import planning validates and replays canonical Area
events from its encrypted event collection. Validation passed: 126 native Rust
tests, Clippy with warnings denied, formatting check, 8 real-WASM portable tests
including encrypted archive framing and import planning, protocol/version checks,
and clean diff checks. Full Chromium lifecycle and accessibility coverage passed

is tagged `kin-v0.15.1`; its annotated tag object and peeled commit were verified
