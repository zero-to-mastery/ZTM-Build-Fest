# v0.40.0 — Restore & Device Migration UX

**Target date:** 2026-10-31

**Status:** Planning contract.

## Goal

Make moving Kin to a new browser/device understandable and testable.

## Prerequisite

The previous release line has passed its gate.

## Product rule

Deliver one understandable household capability without making Kin feel like enterprise project management.

## Architecture constraints

- Preserve canonical event history and deterministic Rust/WASM behavior where the capability enters household state.
- Preserve local-first and encrypted-sync boundaries.
- Keep plaintext household semantics client-side.
- Define persistent-format migration before changing storage.
- Prefer native Web APIs and existing Kin abstractions.
- Do not add AI, scoring, surveillance, or hidden inference.

## Required implementation questions

- What new domain state or event is actually necessary?
- Can existing events/state represent the feature more simply?
- What happens offline?
- What happens across two devices?
- What happens after retry/restart?
- What does export/import do with it?
- Does member/device revocation affect it?
- What are the size/count limits?
- What is the migration from the prior supported version?
- What must be accessible by keyboard/screen reader?

## Daily incubation

```text
v0.40.0 capability
v0.40.1 correctness
v0.40.2 resilience/accessibility
v0.40.3 hardening/polish
```

Do not manufacture empty patch releases.

## Release gate

- End-to-end capability works.
- Relevant Rust/native/WASM/browser tests pass.
- Existing history remains compatible.
- Offline/sync behavior is defined.
- Migration behavior is tested where needed.
- Accessibility is verified.
- Resource limits are explicit.
- Privacy/security claims are honest.
- Docs match implementation.

After completing the October target, stop feature development and gather human feedback. Use patches on the actual completed minor line for concrete defects. Reassess the unscheduled v0.41.x and later plans before starting another feature; October does not require v1.0.0.
