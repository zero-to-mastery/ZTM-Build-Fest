## A. Executive impression

Kin works as a private household board: people could create a household,
pair devices, add things and see them on the other device. The friction was
all in getting started: retyping a 64-character recovery key, iPhone users in
Chrome not knowing how (or that they needed) to install Kin, and having to
type a device name. The test server itself also lost its data once and then
twice failed after a deploy. Each of these was fixed before release (see E).
The next improvements are encrypted device names and nicknames (#71) and a
real-device re-check of the setup screens changed in #199.

## F. Things Kin gets right

- Once set up, adding things and seeing them on the other device worked, which
  is the core of what Kin is for.
- Passkey unlock, once the server kept its data, was quick and felt normal.

## G. Top improvements (up to five)

1. **Re-check the new setup screens on a real iPhone** (#199): whether Safari
   or Chrome offers to save the recovery key, and whether the install steps
   match iOS 26. Benefit: confirms RC-01/RC-02 are gone. Check: a new tester
   sets up without help.
2. **Encrypted device names and nicknames** (#71). Benefit: devices are easy
   to tell apart. Check: People & devices shows names on every member's
   device.

## H. Questions that need real users

- Do people understand the fingerprint comparison when pairing? Ask the next
  testers to describe what they compared.
- Do people actually save the recovery key now that they don't have to retype
  it? Ask during a later recovery drill.
