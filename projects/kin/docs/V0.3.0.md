## Objective and scope

Make short household context easy to pick up without reconstructing a conversation. Add a dedicated Handoff entity, capture form, needs-attention list, recent acknowledged context, acknowledgement, and terminal archival. Preserve Today/Needs behavior and all existing canonical event bytes.

## Non-goals

No Talk, Pulse, routines, summary feed, history browser, restore, editing, recipients, assignment, roles, priority, due dates, attachments, comments, reactions, read receipts, notifications, scoring, timing analytics, accounts, login, member registration, passkeys, invitations, pairing, trusted devices, authorization, encryption, sync, remote services, frameworks, or runtime dependencies. Talk remains future v0.4.0 work.

## Domain and identity

`HouseholdState` retains ordered `items: Vec<ItemState>` and adds ordered `handoffs: Vec<HandoffState>`. A handoff has typed `HandoffId`, exact text, `created_by` and `created_at` from its add envelope, and `HandoffStatus` (Unacknowledged, Acknowledged, Archived). Each collection is ordered by original addition; UI shows newest handoffs first within each status group.

No acknowledgement metadata is duplicated into the projection: its actor/timestamp remain in the immutable acknowledgement envelope. Local actor placeholders provide deterministic provenance, not verified people, membership, or receipt by a named partner. Creator and acknowledger may be the same actor. UI uses only neutral “Acknowledge” / “Acknowledged”. Acknowledgement means enough context has been seen to stop requiring attention; it does not mean agreement, approval, completion, correctness, or acceptance of responsibility.

## Events and lifecycle

Existing kind codes 1–4 and schema interpretations remain unchanged. New kinds use schema 1:

| Code | Kind                 | Exact payload                               |
| ---- | -------------------- | ------------------------------------------- |
| 5    | HANDOFF_ADDED        | handoff_id[16], text_length:u32, UTF-8 text |
| 6    | HANDOFF_ACKNOWLEDGED | handoff_id[16]                              |
| 7    | HANDOFF_ARCHIVED     | handoff_id[16]                              |

Text must be strict UTF-8, 1–4096 bytes, and not whitespace-only. Envelope identity, timestamp, logical time, canonical-byte deduplication, and household validation retain existing semantics. IDs have a separate HandoffId type and namespace, never ItemId; browser additions generate independent random IDs.

| Current state                  | Intent                            | Result                                                |
| ------------------------------ | --------------------------------- | ----------------------------------------------------- |
| absent                         | add                               | unacknowledged                                        |
| unacknowledged                 | acknowledge                       | acknowledged                                          |
| acknowledged                   | acknowledge                       | valid no-op, consistent with repeated item completion |
| unacknowledged or acknowledged | archive                           | archived tombstone                                    |
| absent                         | acknowledge or archive            | domain error                                          |
| archived                       | any mutation                      | domain error                                          |
| existing                       | distinct add with same handoff ID | domain error                                          |

Exact duplicate delivery is idempotent; conflicting event-ID reuse fails. Invalid streams yield no partial state and append nothing. Archive never deletes history.

## Protocol and Rust projection

Introduce explicit protocol v3. Requests retain the 12-byte KINE header and 88-byte event envelope, with version 3. No reserved byte is repurposed. Integers remain little-endian, with strict exact-length parsing, 10,000 events, and 64 MiB request/result limits.

| Protocol | Accepted events                               | Result                                       |
| -------- | --------------------------------------------- | -------------------------------------------- |
| 1        | kinds 1–2, schema 1                           | historical Today active/completed items only |
| 2        | kinds 1–4; add schema 1/2, lifecycle schema 1 | classified Item state                        |
| 3        | all v2 events plus kinds 5–7 schema 1         | classified Items and Handoffs                |

Protocols 1/2 reject Handoff events and cannot encode any Handoff state, including tombstones. They are never lossy compatibility views. New browser calls write protocol 3. KERR remains protocol 1 with unchanged categories.

The v3 KINS header is `magic[4] | version:u16=3 | reserved:u16=0 | item_count:u32 | handoff_count:u32` (16 bytes). It is followed by all v2-layout Item records, then all Handoff records. A Handoff record is `handoff_id[16] | created_by[16] | created_at:i64 | status:u8 | reserved[3]=0 | text_length:u32 | text` (48 fixed bytes). Status codes are 0 unacknowledged, 1 acknowledged, 2 archived. Combined entity count cannot exceed 10,000. Empty v3 state is 16 bytes. Earlier result layouts remain unchanged.

Rust owns decoding, payload/domain validation, lifecycle, mixed replay, projection, and serialization. JavaScript encodes intents and decodes results but never maintains a second reducer.

## Browser commands, storage, and drafts

Use native bubbling/composed commands: `kin:add-handoff { text }`, `kin:acknowledge-handoff { handoffId }`, `kin:archive-handoff { handoffId }`. A focused `kin-handoff-list` component renders lists and a separate capture form; `kin-app` owns persistence, replay, retry, focus, and busy state. No Item classification selector appears in Handoff capture.

IndexedDB remains schema 1: the existing events/local_context stores hold new canonical bytes without structural changes or migrations. Candidate events are validated by Rust inside the serialized write transaction; event and counter commit/abort together. BroadcastChannel sends only the existing content-free invalidation.

The Handoff draft uses its own tab-scoped `kin.handoff.draft` sessionStorage key. Storage denial must not prevent capture. A successful operation clears only its submitted text snapshot; retries reuse original text and never clear a newer draft. Busy state disables all capture/action/retry controls. Peer refresh reloads canonical bytes through Rust; unavailable action retries clear against that projection. Archived handoffs are omitted from normal views.

## v0.3.4 retry recovery

User-authorized follow-up patch: a failed canonical refresh retains the original failed command and feedback in transient application memory. Repeated refresh failure offers refresh retry first; successful Rust replay restores the command retry unless canonical state invalidates it. No automatic append occurs on refresh recovery. New commands supersede suspended retries. Browser regressions cover Handoff add/acknowledge/archive, Item add, repeated failure, newer drafts, stale peer actions and supersession. This is not persisted household state or a new capability.
