# Markdown Style Guide

This guide defines practical Markdown standards for open.blog content quality.

## Baseline principles

- Write in plain Markdown first.
- Keep structure semantic (headings, lists, blockquotes).
- Keep line length readable in source.
- Prefer descriptive link text over raw URLs.

## Headings

- Use one `#` heading per document body.
- Start sections at `##` and descend sequentially.
- Avoid skipping levels (`##` directly to `####`).

## Links

- Use descriptive labels: `[CLI command reference](...)`.
- Avoid “click here” style anchors.
- Use relative links for internal content portability where possible.

## Images

- Always provide meaningful alt text.
- Use images only when they add instructional value.
- Keep filenames predictable and descriptive.

## Callouts and blocks

open.blog supports callout-style blockquotes (for example tips and warnings). Use these for guidance, not for normal paragraphs.

## Code blocks

- Fence all code blocks with triple backticks.
- Include language tags for syntax highlighting.
- Keep samples minimal and executable where possible.
