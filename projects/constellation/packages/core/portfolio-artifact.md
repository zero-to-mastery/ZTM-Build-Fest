# Portable Portfolio Artifact v1

Core exports a portable directory artifact from a validated Semantic Graph v1. The manifest records the unchanged Scene v1 and semantic contract versions, a stable subject identity and fingerprint, and SHA-256 digests and UTF-8 byte lengths for every asset. The directory contains the canonical graph, projected `scene.json`, accessible static SVG fallback, standalone interactive HTML, Semantic Markdown, and `manifest.json`. The HTML uses the existing renderer/runtime and embeds its runtime, so deployment requires no Studio, GitHub access, remote code, or separate WASM file.

```js
import { createPortfolioArtifact, validatePortfolioArtifact } from '@constellation/core';

const artifact = await createPortfolioArtifact(semanticGraph);
await validatePortfolioArtifact(artifact.files['manifest.json'], artifact.files);
```

Creation and validation use Web Crypto SHA-256. Validation bounds the manifest to 16 KiB, each file to 16 MiB, the bundle to 32 MiB, and the asset count to 12. It validates Scene v1 and Semantic Graph v1, checks their subject and fingerprint agree with the manifest, checks Scene project identities exist in the graph, and rejects unsupported versions, missing or mismatched digests, unsafe paths, unexpected executable filenames, and incorrect entry points. Listed assets are limited to `constellation.html`, `constellation.svg`, and JSON, Markdown, or text data. The Scene must belong to the manifest subject: its account is the subject or, for a developer Atlas drill-down, the owner of one of the graph's projects, and any project root must be a graph project. The static SVG may not contain scripts, event-handler attributes, `javascript:` URLs, or embedded documents. `constellation.html` is the only executable artifact and is generated by Core from the validated Scene. Consumers must obtain the manifest and files from a trusted distribution channel; hashes detect corruption and mismatch, not a maliciously replaced manifest. Artifacts written by Constellation 4.7 or later are accepted; the manifest, Scene and semantic contract versions are what guard format compatibility.

The artifact preserves source-backed identities and evidence through the semantic graph and embeds a matching scene for direct component loading. It contains no credentials, session state, or user-authored executable configuration. Static `constellation.svg` remains usable when JavaScript or WebAssembly is unavailable. The standalone HTML entry embeds the generated runtime and WASM; validation checks its offline runtime marker and CSP in addition to validating the Scene, paths, sizes, and digests. Web Component integrations may load `scene.json` with `src`, or set the validated scene property directly; the standalone HTML needs no network after it is downloaded.

Create the directory form offline with `constellation --semantic-graph input.json --format portfolio --output ./dist/portfolio`. The destination must be new or empty; this avoids mixing unvalidated files into the artifact. In the Studio, **Get it** → **Put it on a website** → **Download portfolio package** downloads a single JSON container with the same manifest and named files; unpack the files before static hosting. Studio reports setup only and does not verify deployment. The CLI directory form is the preferred package-manager workflow for deployment automation.

Local Node.js 22.12.0 diagnostics: 12 projects created in 41.9 ms and validated in 4.8 ms (1,169,743 asset bytes); 100 projects created in 62.9 ms and validated in 9.1 ms (1,434,090 asset bytes). A 45-node standalone HTML bundle measured 1,196,237 total bytes with the existing 1,040,342-byte runtime and 670,680-byte WASM. These are local single-run timings, not device or network guarantees.

The isolated headless Chromium consumer fixture measured 338.7 ms from package import to first readiness, 0.6 ms for project and relationship focus, 58.1 ms for five widths from 240px to 1280px, and 2.6 ms for disconnect/reconnect. It uses local package copies and localhost; no live GitHub requests are needed. The React 19.3.0/Vite 8.3.4 and Astro 5.18.2 fixtures also run in Chromium against copied package artifacts. React assigns Scene data through a ref and removes native event listeners on unmount. Astro loads `scene.json` separately, so replacing the artifact does not require rebuilding the host.

Framework integrations use the same packaged Custom Element and public Scene property. React and Astro consumer fixtures are in `fixtures/consumer-react` and `fixtures/consumer-astro`; the Chromium suite exercises actual mounting, readiness, errors, project focus, and evidence-backed relationship focus. The test workflow installs their pinned, fixture-only framework dependencies before running tests. The published Core and Web Component packages have no React or Astro dependency. Vite and Astro must keep `@constellation/core`, its browser runtime subpath, and the Web Component package out of dependency pre-bundling so the existing top-level-await WASM loader remains browser-native. Hosts should observe both `scene-ready` and `scene-change`: a connected element may initialize before an app assigns its authored Scene. Plain HTML uses the published import map from [the Web Component guide](web-component.md).

The validator rejects malformed manifest and asset containers, excess asset counts, invalid size/digest metadata before encoding asset content, unsupported runtime references, bad entry points, executable SVG content, missing CSP/offline runtime markers, Scene/graph identity mismatch, and corrupted digests. Digests are integrity checks and do not authenticate the manifest itself; distribute the complete artifact through a trusted channel.

To run the real framework browser fixtures locally, install each isolated fixture's dependencies with `npm install --prefix fixtures/consumer-react` and `npm install --prefix fixtures/consumer-astro`, then run `node --test --test-concurrency=1 test/framework-consumer.test.mjs`. These dependencies are not part of the published package dependency graph.
